# CimiLoop 原执行终态与账单核对实施设计

D-261，基于 D-260 / b8fde0d。完整 V1-09 / V1-21 / V1-22 / V1-10 / V1-11 保持；真实模型／套餐／现金积分批准、实际账单认证和专用 Native / Bun 故障仍未解决，不进行付费调用。

本批把原执行结果、原账单和 Kernel 全部未知观测接成 ReconcileRun，而非继续增加查询记录。只接受保留原 command_id 的空 payload Human 请求，原 terminal 与金额不能从 HTTP / CLI 指定。

1. 新终态核验器按原 operation 同步独立读取保留的 Native 配置5、控制器2、原机器二进制／控制器证明及实际当前原文件，必须与已采集原字节相同。要求原进程停止、资源已处置、未被取消、原 IPC / 模型 / Native 调用均无未决。成功需既有独立 Task 产物／SDK／Native 再验；失败需原 Native 退出／期限负面证明，且独立文件／检查账本与完整 IPC 一致。仅模型文字、账单齐全、资源处置或旧格式不能构造终态。
2. 原账单继续由 D-260 逐笔 reader 读取真实账单 Ledger 与模型原件；费用币种必须等于原 Run。新增私有 reconciliation request / proof / prepared 1.0.0，保存终态绑定、全部原未知观测引用及原费用，Kernel 读取时再验 Native 原件、执行与账单，不能靠已存 JSON 结清。
3. 新共享 Human reconcile 方法复用 Kernel 原 ReconcileRun。只在独立终态与完整已知费用满足时结清父 Run、释放剩余成本预约并保留已消费现金；不满足 Task、不返还启动次数、不授权新 Run。原回执重放不再采集／打开账户，响应丢失与释放失败保留原 Command；旧观测／费用记录保持旧格式和 Unknown 语义。
4. 接工作台独立原执行／费用核对、同一编译 CLI reconcile-original 命令及原请求持久恢复。模型／账单／Native 资格均只能由代码端口安装；默认正式 Agent 关闭。
5. TDD 用实际 SQLite / Kernel / 本机 TLS / 账单契约组合测试成功和失败及全未知引用覆盖、篡改原件、缺账单、提交后恢复。受控 Native / SDK 读取端口只证明程序契约，不能作为实际 Native / 模型 / Skill / Matt / Superpowers / S1 验收。实际 Windows 未有强终态时必须拒绝结清且保留费用和预算；不重复三轮相同 Bun 崩溃，不禁用 EDR 或替换原执行二进制。
