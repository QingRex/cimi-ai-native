## 操作闭环

首次安装可通过 `runtime install-codex --placement-root` 显式选择同卷仓库外根，保存本项目原放置选择；后续不带选项仍读原选择。已有 legacy 安装不自动迁移或遮蔽。原选择／安装缺失保持不可用，不从另一根补齐。安装字节、账号和固定检查仍使用原安装封口。

`runtime allocate-codex-budget` 从已经安装的原账户政策永久预留模型次数与最大输出 token，到目标同卷 Host1 子政策。源、目标都经 Kernel 当前 Human 项目负责人核对，所有 await 后及原效果前复查对象、身份和权限。原账户必须匹配 target 已安装的账号和 ordinary quota 摘要，不能用另一账号或新建预算补足。

本批选用有限分配而非复制旧账本：复制会改变 Host 物理身份，不能保持原预约。父先占额度、子后凭真实能力拨入；未拨入的子政策不能预约模型，复制 JSON 或另一个同上限目标不能得到拨入能力。分配本身及旧 Unknown 永不自动释放。子政策和父的后续消费合计受原父有限总额约束；不宣称真实 cash／credit／provider quota 已预留或已结清。

目标 intent 先于子政策建立；后续父占用、拨入、附件按原身份幂等。拨入完成而附件响应丢失可继续同请求，不重复占父容量；原 intent 后子根或政策缺失拒绝重建。完整附件重放和后续 Runtime 仅打开本地子账本及其资金证明，不持续持有系统盘父账户或全局 registry 的写句柄。私有 WeakMap 仍在原账户模块登记实际写根，复制租约没有路径权威。

实现使用现有 Host1 immutable tickets 与 capacity_policy／capacity_hold，不改 DDL，不升级用户库。新分配附件为内部 format2；旧 format1 继续原路径、原身份打开，不自动转换。普通 install-codex-budget 遇到已开始分配的项目即拒绝，不能绕过未完成拨入。

接入命令与恢复边界见[指南](../implementation/CimiLoop-Codex同卷安装与有限额度分配-v0.1.md)。该指南尚未在完整真实配置上执行成功。
