## 可执行能力

`CodexFactInvestigator` 接受明确安装且冻结的源码快照。子会话仅能用 `read_fact` 读取清单内原文件，不能询问 Human、执行命令、访问任意路径、委派其他模型或修改业务状态。子操作身份固定取父操作和原 callId 的摘要；变更问题或输入不能在同一 callId 下另开执行。每条观察必须引用本次实际读取过的文件；观察语义是否正确仍需独立核验。

`CodexFixedClarificationMethod` 可安装该调查器，要求先读取全部固定 Skill／输入，再委派环境事实调查；每操作最多四次。返回 Human frontier 时仍只记录待回答问题和建议，不能伪造回答、Decision、Plan 或 Task。返回值继续明确为 `unqualified_method_execution`。当前调查是等待式工具调用；尚未实现上游要求的“调查未结束时先问独立 frontier”，不能把它登记为完整方法资格。

父调用将真实 callId、线程、回合、模型、非敏感账户指纹及 AbortSignal 交给子工具。子模型／账户必须在子模型请求前匹配父准入。停止或超时传播至子执行，关闭后效果守卫拒绝新效果；没有封口证据的原操作保持 pending，重试只读原件，不创建替代回合。实际两个 Node stdio 子进程的取消测试覆盖该行为，不等于 Windows/AppContainer 全异常恢复验收。

## 工具与启动核对

旧实现的空 MCP 表会与用户配置合并，不能禁用已有服务。新启动记录格式 `cimiloop/codex-method-start/2.0.0` 固定明确禁用的已配置服务器名称和全部启动配置；模型请求前读取真实 `mcpServerStatus/list`，只允许明确禁用、状态为 disabled 且无工具／资源的条目。未知或活动服务、分页残留均拒绝。不会为不存在的服务器伪造缺失传输配置。

保留 CLI 必需的内置 `code_mode_host` 来派发显式动态工具；关闭 `code_mode`、computer/browser、plugins 等入口。这不等于完整隔离资格。实际接入中发现关闭该内置宿主会使所有固定工具不可用，因此旧的“全部工具宿主关闭”不能作为成功条件。原件核验还要求所有效果均为白名单动态工具，拒绝命令等未批准事件。

线程初始化可能在初次账户读取后发送延迟 ChatGPT 登录通知；现在先核对工具目录，再新鲜读取同一账户。发送模型请求前排空已收到的消息队列，再检查账户是否变化；避免同一字节块中的账户通知被 RPC 唤醒顺序越过。运行中的账户更新仍拒绝。账户响应验证失败时原 RPC 会被拒绝，不会因先移出 pending 表而永久悬挂。

私有启动格式1保留原配置并允许历史读取；不改写既有原件，不因此授权新效果。实际旧操作 `f4ae2af2-01ff-46ec-ae1f-5ebe77dcb910` 在新源码下只读重放一致，未发送模型请求；其原摘要仍为 `6537f4e598b892409d937caa861bdf866cb12ebc95b866c7eee38838f698111e`。Schema242、项目库10及 Host1不变。
