## 新电脑环境与资料边界

1. 拉取 `origin/main`，先检查当前分支、提交和工作区，保留新电脑已有改动；不要 reset / clean / 强推。若远程已有更新，以新的实际状态重新核对。
2. 仓库要求 Node `>=24.15 <25`，packageManager 为 `pnpm@12.4.2`；上一电脑使用 Node 24.15.0。执行 `pnpm install --frozen-lockfile`、`pnpm check`，不要静默更新 lockfile 或 Provider。
3. 当前真实原生运行依赖 Windows x64 / AppContainer，以及 `%SystemRoot%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`。OpenCode 场景固定 1.18.34，测试读取 `%APPDATA%\npm\node_modules\opencode-ai\node_modules\opencode-windows-x64\bin\opencode.exe`；先核对安装版本、路径与原摘要。其他平台跳过这些测试，不构成原生能力通过。
4. `node_modules/`、`dist/`、`.cimiloop/`、`*.tsbuildinfo` 被 Git 忽略，需要在新电脑安装 / 构建；旧电脑的原始本地回归输出不随 Git 推送。已提交的研究记录保留命令、源码摘要、初次失败和最终验证范围。新电脑要复验，不能假设忽略目录或旧绝对路径存在。
5. 用户只确认使用智谱提供方；具体型号、Coding Plan 或按量套餐、现金 / 积分上限还未确认。此前配置过的连接及价格观察不代表当前正式授权。确认前继续实现与离线测试，不进行付费请求。
6. 专用凭据位于仓库外，当前读取实现使用 Windows DPAPI `CurrentUser`；新电脑需要在自己的用户环境重新配置连接及对应摘要，不要把旧 DPAPI 文件当成可直接使用的跨机器凭据。API Key 不进入提示词、Git、日志、Agent 上下文或研究记录。
7. 旧电脑仍有缺少原登记的历史 Unknown 资源，详见[启动恢复边界](../implementation/CimiLoop-OpenCode启动资源登记与恢复-v0.1.md)。新电脑不能用本机“找不到进程 / 映射”证明旧资源已清理；不要补造归属或批量删除旧 Temp / 映射 / Profile。数据库升级只能按显式迁移和具体授权执行，尚未升级用户项目库。
