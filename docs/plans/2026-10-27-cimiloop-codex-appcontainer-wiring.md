# Codex 原模型 Job 的 AppContainer 接入

接续 `edbaea4`。完整 S1 五组继续，默认正式 Agent 仍要求完整生产来源。本批将模型进程的 OS 边界装入实际默认组合；不读取登录文件、不发送真实模型请求、不升级用户库。

## 已实现的执行路径

普通 Run、Skill 子调用、Skill 隔离调用和 Runtime 技术契约四处默认组合，将已取得的 `FixedVolumeRuntimeStorage` 传入 `CodexOriginalMethodRuntime`。模型调用从该能力的私有状态读取原项目范围、配额票据和 Runtime 票据，核对原 Host1；不调用可替换的公开 `read()`，配置 JSON 和复制对象不能授权。每次效果前重新核对实际原卷及相关路径。缺少能力时在创建模型目录或登记进程前拒绝，不回退普通用户令牌。

新内部 start12 固定同卷约束、原票据和两处写根：原操作 `state` 与已批准的仓库外官方登录目录。模型 header23／24／25 分别延续普通工作区、父 Skill 工作区、具名方法的原工具协议，同时绑定项目身份和禁止降级。只读重开只消费已有原票据、Job 原件及结果，不能从记录恢复新执行能力。旧 start1–11、模型 header1–22、launch1／2 继续按原义读取，不升级旧 pending，不自动迁移 Schema242、项目库10或 Host1。

launch4 使用每次原 nonce 对应的新 AppContainer Profile，并原子加入原 Job 后挂起核验实际 token；随后限制本次 Profile 文件和注册表写入、固定目录身份，再恢复工作进程。只给两处写根继承 Modify、程序文件 ReadAndExecute；工作目录只给遍历和属性读取。没有桌面／window station ACL 修改、UI 能力、loopback 豁免或旧 Profile 采用。默认模型网络模式为 `deny_all`。低层可表达的 `public_internet` 没有在默认组合启用，也没有被当作主机白名单或完整生产网络来源。

实际 Windows 会将 AppContainer 的 TEMP 重写到原私有 LOCALAPPDATA 下的 `Packages/<原Profile小写名>/AC/Temp`。上层现在按原 launch nonce 在已批准 state 根内准备该目录，并将物理身份纳入效果前核对。不会创建系统盘包目录作为可写回退，不改变父进程环境，不复制登录文件。

Job 取消和宿主退出继续处理原操作。新 start3／end3 保存 OS Profile、包 SID、两处写根身份和网络模式。只有整个 Job 活动进程数归零、Job 关闭、精确移除本次授权且复读 ACL 确认、本次 Profile 删除成功后，才保存结束证明。任一步缺失保留 Unknown；非零退出、取消或资源已清理都不能变成成功模型原件或费用已结清。资源读取器现支持新的原 Job；不以 PID 缺失单独证明回收，不重派调用。
