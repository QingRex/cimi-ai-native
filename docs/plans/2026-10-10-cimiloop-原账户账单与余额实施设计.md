# CimiLoop 原账户账单与余额实施设计

D-258，2026-10-10，基于 D-257 / 790f05d。本批实现原账单接收、不可变三方历史、原占用匹配、账户剩余额度和共享 Human 原 Run 查询。五组 S1 目标不变。

1. 原占用和请求字节永久保留。仅显式新建、启用账单的账户使用 AccountOrigin body2、私有账户 SQLite2；旧 body1/SQLite1原样读取、保持保守占用、拒绝原位安装账单，不自动升级任何用户库。公开242 Schema、项目库10、原启动账本1不变。私有独立账单 SQLite1 使用新 application_id=0x434d4231，与账户 SQLite2 不混淆。
2. 原身份同时在账户 SQL 和 Host ticket 固定独立 billing.sqlite 物理身份、完整政策摘要、核验代码身份、现金币种及积分单位。代码安装的同步独立端口每次审核原提供方账单认证、历史批准/套餐/费率、请求归属及最终性；不猜智谱 API，不读取真实凭据，不发付费请求。无端口或核验失败拒绝。usage、截图、导入JSON、取消、响应成功和进程消失不能结清。
3. 账户 writer transaction 先追加不可变 account_bills 意图，随后 Host 独立提交、billing SQLite 独立提交，最后父账户事务提交。每次读取/占用/重放完整核对意图、Host、bill原字节与投影三方，缺任一历史拒绝，不能补写修复/退款/重发。Host与bill两边同时自洽删行的红例已证明需要第三意图；不宣称管理员毁掉所有独立安全原件后仍可恢复证明。
4. 每份账单保存原字节/摘要、独立投影和核验身份。每项匹配原request_id/call_id/scope/请求及占用摘要，同请求仅结账一次。相同bill_id+原字节+投影精确重放，变更/重叠拒绝，多项一次入账。原字节最多16KiB、每份1–64项，完整记录最多60,000字节，保留共享Host1024票据和64KiB边界；容量不足保留已有原件，不删除历史。
5. 现金/积分可用额度同时计入实际最终费用及未决原上限，以BigInt计算。真实超原单次上限或总预算费用完整保存并冻结新增请求，不截断费用或批准额外额度。历史0占用仍为Unknown，不自动认定0费用。账单事实不代表模型、Run、Task、Skill成功或Kernel正式结算。
6. 原账户Windows主库及billing主库/WAL/SHM/journal每次新鲜核验ACL/物理身份；实际子进程并发账单仅一笔生效，相同原件返回重放。共享LocalAgentAccountBilling只读入口使用Human原项目/Run的Kernel读取权限，取消后可查询；HTTP/CLI JSON不能安装核验器、选择账户根或改变调用者。

公开构造认证/模型/批准/套餐/费率用于合同与实际Windows可执行链路验证，不是实际智谱账单认证或S1验收。仍须接实际账单核验端口、独立SDK请求与真实账户身份认证、Kernel费用ReconcileRun、物理硬配额、完整恢复及全部五组。正式默认Agent保持关闭，真实Key读取和付费请求0；模型/套餐/现金与积分上限待用户确认。
