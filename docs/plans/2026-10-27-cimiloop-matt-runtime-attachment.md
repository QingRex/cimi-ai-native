## 本批新增操作

`clarification attach-codex-runtime` 将原 Matt 来源接到既有正式 Runtime 安装、共享有限账户、固定卷及仓库外登录目录。它打开已有来源，不读取登录令牌、不发送模型请求、不创建业务 Run，也不批准 Provider。成功安装重复执行使用同一受保护登记；默认 CLI 和工作台随后复用该组合。

原独立 Matt 来源和全部历史原件继续保留。新组合使用 Runtime 的原程序和 companion 包、私有登录与环境、固定卷写域、受限网络、内存 Job、原卷句柄和显式包权限。模型／账户不一致、缺少真实来源能力、部分安装或物理目录替换均拒绝，不从空目录重建原件。配置级 `usage_policy` 不与私有状态政策混用；新父方法和事实调查请求按已固定账户记录请求级政策，旧请求字节不变。

**当前真实发送仍不可用。** 输出预约不等于模型输出上界；固定官方 Codex HTTP／WebSocket 请求都未设置输出 cap，而且一个 app-server turn 可包含多个生成及重试。新受控 transport 在 prepare 和 execute 中均于模型效果及预约前拒绝 `codex_pre_plan_output_budget_unavailable`。安装结果明确返回 `model_dispatch_available:false`。不能将本批装配称为真实 Matt 已执行，不能用事后拒绝或降低思考强度替代服务端上界。

接入步骤已纳入[真实接入指南](../implementation/CimiLoop-S1真实接入与验收操作指南-v0.1.md)第3.1节；该指南仍未完整实走。

## 原身份、核验和资源所有权

共享账户增加明确的 pre-plan 预约身份：项目、Human、原会话、invocation、call、原请求与原安装摘要；不制造临时 Run。它与 Agent／子 Skill 使用同一容量账户，Unknown 不返还；Run 原模型读取只排除核对完整身份、键和单位的 pre-plan 行。当前新受控 transport 尚不调用该预约入口，因缺少真实发送上界。
