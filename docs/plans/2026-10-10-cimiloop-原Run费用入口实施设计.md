# CimiLoop 原 Run 费用入口实施设计

D-259，基于 D-258 / 3a244c6。完整五组 S1 继续，本批将已有账户费用读取接入 CLI 与工作台；专用 Native 连续段错误仍未解决，不计组合成功。

1. 共享 Human 服务先读取原项目、Human 入口及 Kernel 原 Run 对象，再调用代码安装的账户工厂。工厂只能打开原已登记账户，返回真实 DedicatedAgentAccountLedger 与 release 函数，不启动模型、写账单或重新预约。HTTP／CLI 参数不能选择工厂、账户根、凭据或核验器。默认不安装提供方账单核验器。
2. 每次工厂、释放等异步等待之后重新读取 Human 入口和原 Run 的 scope／record／context，任何变化拒绝。释放无论查询成功或失败均执行；查询或释放失败不泄露原异常文本，费用显示待核对，不补账、不显示零费用。
3. GET /api/agent-runs/:run/costs 使用既有回环 Host／Origin／会话检查，异步查询之后再次核对会话与关闭状态。不接受查询参数、写请求、原件／身份／路径覆盖。没有工厂返回明确能力缺项，取消后的原 Run 仍可读取。
4. 工作台以独立只读按钮显示核定现金、积分微单位、原占用和未决数量。无原账单不显示费用0；部分账单仅显示已核定部分。账户账单齐全不代表任务／Kernel 已结算。读取丢响应可重新查询同一 Run，不写领域幂等请求槽、不启动或改变预算。并发查询只采纳最新请求，卡片移除后迟到成功或失败不修改新页面与提示。
5. CLI 的 run costs <run-id> 复用同一共享服务。普通 CLI 默认缺少账户工厂时拒绝；受信代码启动器可安装同一命令与账户工厂，真实编译后的 CLI 命令用实际 SQLite 原件验证。不能通过 JSON、环境变量或动态模块路径安装核验器。
6. 验证先红后绿：实际 Kernel／账户／账单原件、HTTP 会话与异步撤销／关闭、释放失败、取消后读取、浏览器丢响应重读、CLI 参数拒绝与稳定 JSON。另复验实际 Windows 账单保管；不将上批 Native 失败或未运行的组合算通过。

公开构造账单认证、账户批准和领域资格仅用于可执行合同验证；真实智谱、Skill、Matt、Superpowers、正式费用 ReconcileRun、物理硬配额及完整 S1 仍未完成。项目库10、242 Schema、原启动账本1及 D-258 的显式新账单账户格式2／旧账户格式1保持；本批不迁移用户库，不付费、不读取真实凭据、不 push。
