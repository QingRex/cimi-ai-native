# Runtime 安装与共享账户可写范围

接续 `ce05f0d`，继续 V1-09 的完整物理配额要求。此前生产普通／父Run及Skill子调用只核对项目、数据根和固定卷登录目录，安装账本、共享账户／注册账本与工具目录仍可能留在系统盘。本批将这些真实来源接入同一个执行前守卫，不把项目位于配额卷上当作全部Runtime可写路径已经受控。

## 已实现

默认安装读取器在打开实际受保护Host后，私有保存原安装账本根与工具根；默认账户读取器私有保存原账户、共享注册账本和账户工具根。只有真实打开的来源对象拥有这些路径身份，复制对象或请求JSON中的writable_paths不能取得它。给账户追加更严格Runtime租约守卫时，显式继承原来源身份，释放原租约后同样失效，不发行新账户／预算。

普通／父Codex Runtime和Codex Skill子调用，在准备和每次原效果守卫中取得这些固定路径，再核对同一原项目／数据根、原Host、原登录目录与原配额。任一安装、账户、注册或工具根在卷外即拒绝，不启动模型或Native；这个拒绝不清理、移动或重建任何原资源。采集、查询与历史回执不因缺少新的执行条件而被当成可重新运行。

物理路径核对使用真实FixedVolumeRuntimeStorage能力。新增批量读取在一次守卫中取得前后原卷与Host依据，对全部普通路径核对相同卷根并在最后重读路径；不缓存跨效果许可。六个额外根的核对使用固定四次OS观察，不为每个根重复打开磁盘读取器。实际项目与数据根仍由原储存能力内部独立核对。

没有新增公共Schema、数据库字段或格式；Schema242／项目库10／Host1保持。新的路径身份仅属于当前代码租约，不持久化为可导入的授权标记，不补写旧资格或批准。

## 仍须继续完成

现有本机安装和共享账户目录实际仍可能在系统盘，本批不会把它们自动搬到配额卷。完整可用接入还须提供显式兼容的安装／共享账户放置或迁移，保留原账户容量、Unknown预约、Host身份与历史读取；不能通过换环境目录重新初始化预算来冒充迁移。真实固定卷prepared.json和同卷仓库外官方登录目录仍待提供；只填写镜像路径不替代这项实现。
