# D-253 工作台原 Agent 启动衔接实施设计

完整五组 S1 继续。工作台目前只有查询、停止、采集与原观测入口，已有共享 LocalAgentRuntimeStart / LocalAgentRuntimeComposition 没有接入页面启动路径。直接从 Human 构造 Agent Caller 或让 HTTP 选择模型会绕过领域和宿主权威；直接复制 Runtime 启动流程会产生第二套原登记。采用 Kernel 只读核验当前 Human 技术负责人指派，受信宿主工厂返回原 Agent 的现有组合，共享 Human 请求服务核对同一项目 / 原 Scope，在异步准备前后及实际Native配置发送 / 各准备继续 / SDK恢复放行前重新核权，最终复用原唯一启动服务。

POST /api/agent-runs/:id/start 只接受空对象，不接受提供方、模型、路径、Actor 或预算覆盖。受信工厂只由本机代码安装，默认入口缺工厂而拒绝。工厂不得启动效果，模型 / 账户 / 原预算及 Native 准入仍由原组合的当前检查负责。已批准的原 Run 可请求启动，启动不会创建新 Run、增加预约次数、产生 Task 成功或结清费用。同 Run 并发和丢响应继续使用既有原登记，不因新电脑缺文件重开 Run。

浏览器为每个原 Run 单独保留启动请求身份，发送前持久保存，丢响应后明确核对同一原启动；不占停止 / 观测的业务命令待核对栏，因此长运行期间仍能查询和请求停止。原启动存储不可读取仅禁用启动，查询 / 停止继续；测试关闭前需等待启动与停止的HTTP / JSON / 页面刷新全部结束。其他浏览器命令保持原 Kernel 规则。

先验证默认无完整组合拒绝和 HTTP 覆盖拒绝、Human / Agent 启动请求权限，再实施共享服务与 UI。覆盖实际 HTTP / DOM 丢响应接续、撤销 / 外来组合拒绝及现有原控制；将现有实际 Windows 读查 / 读改查组合通过新的工作台启动入口执行，并覆盖最终模型准入等待期间真实Kernel撤销Human权限后不恢复SDK，保持构造模型 / 资格边界。242 Schema、用户库10和原启动账本1保持，不升级用户库。验证、更新文档后仅本地提交；真实模型 / 账户、Skill、完整方法验证与五组 S1 不以此批代替。
