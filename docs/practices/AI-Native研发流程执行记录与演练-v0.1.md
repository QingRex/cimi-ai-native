# AI Native 研发流程：执行记录与演练 v0.1

> 日期：2026-10-02。
> 依据：[现行流程基线](../architecture/AI-Native软件研发流程-v0.1.md)。本文是配套工作材料，不新增生命周期或产品实现要求。
> 状态：模板与虚构填写示例已编写，真实演练尚未执行。下文人名、编号、版本、时间、结果及证据代号均用于演示，不能作为实际验收、授权或发布依据。

## 1. 使用方式与团队约定

优先把这些内容填入已有需求、任务、评审和发布记录，用链接关联即可，不要求创建四份独立文档。不适用项说明原因，未知项写出负责人和下一次检查时点。真实证据应链接到可复查的代码版本、报告或操作记录，不只填写“通过”。

试运行前由团队填写以下约定；右列仅示范写法，不是所有团队统一默认值。

| 约定 | 示例值 |
|---|---|
| 交付协调人 / 优先级争议裁决人 | 林（开发负责人）/ 周（项目负责人）；姓名均为虚构 |
| 开工依据 | 需求负责人说明价值、紧急程度与依赖；林结合开发、评审、测试和发布容量安排 |
| 在制上限 | 同时推进 3 条需求；含等待评审、测试和发布，按需求计数，不按 Agent 数量计数 |
| 暂停与紧急插入 | 暂停保留负责人、原因、资源占用和恢复检查时间；紧急插入说明被影响需求，恢复时重查容量 |
| 容量检查 | 每个工作日检查一次；出现阻塞、紧急插入或环境延期时即时调整 |
| 常规授权 | 技术负责人批准的纯展示修复，可修改指定目录并运行本地测试；不含合并、部署和生产操作；任务范围改变或授权撤销即失效 |
| 预算与停止条件 | 每任务在开工时明确；示例为最多 2 次失败修复循环、2 小时主动处理时间，超限先汇报事实与选项 |
| 环境责任 | 每批指定发布负责人和环境恢复负责人，记录占用结束或复查时间；替代环境及恢复时限按本批约定 |

## 2. 可直接填写的最小记录

### 2.1 需求与验收

| 项目 | 填写内容 |
|---|---|
| 身份与来源 | 编号、需求 / 缺陷类型、原始诉求与来源链接 |
| 责任与排序 | 需求负责人、优先级依据、开工安排；目标版本可空 |
| 当前约定 | 需求版本、确认人及时间；目标、范围、非目标、约束 |
| 验收标准 | 实施前确认的关键场景及预期；技术改造写效果与兼容约束 |
| 交付终点与知识义务 | 对谁提供何种能力；上线前及关闭前的必要材料 |
| 未知与依赖 | 关键未知、处理人、检查时间；依赖其他需求时写明方向 |

### 2.2 任务、授权与接续

| 项目 | 填写内容 |
|---|---|
| 任务与计划版本 | 目标、输入依据、输出、依赖、技术确认人 |
| 工作基线 | 仓库、确定提交、分支 / 工作区；未提交差异的安全保存位置 |
| 操作范围 | 可改内容、可用环境与工具；授权来源、有效条件与撤销方式 |
| 验证与停止 | 验证方法、预算、重试限制、请求判断的触发条件 |
| 当前进展 | 已完成事项、证据、未解决问题与负责人 |
| 接续安排 | 下一步、接续者；实际代码、需求、计划与授权的核对结果 |

### 2.3 验证与待验证项

| 验收项 | 对象与条件 | 自检依据 | 独立评价依据与评价者 | 结论 / 缺口 | 接续负责人及检查时点 |
|---|---|---|---|---|---|
| 填写场景编号 | 提交或制品摘要、配置、环境、数据条件 | 原始报告引用 | 独立读取的需求版本、检查及报告引用 | 通过 / 失败 / 未知及适用范围 | 无遗留也明确写出 |

内容变化后记录哪些结论仍适用、依据是什么、需要补哪些检查。独立 AI 会话须直接读取原始依据，不以执行者总结作为唯一输入；高风险项记录专业人员实际检查结论。

### 2.4 发布、交付与复盘

| 项目 | 填写内容 |
|---|---|
| 确定候选 | 发布编号、来源提交、制品完整摘要、实际需求范围与依赖；配置、开关、数据结构及迁移版本 |
| 验收与决定 | 各需求负责人验收、涉及产品行为的产品判断、测试质量结论、发布负责人授权及有效条件 |
| 环境与恢复 | 目标环境、占用时间、必要测试数据恢复引用、兼容检查、恢复负责人及操作边界 |
| 生产验证 | 即时检查、失败判据、观察窗口、恢复触发条件及实际结果；未知状态先核实 |
| 实际交付 | 逐条实际结果、知识义务、需求负责人完成确认；延期和未交付项单列 |
| 后续义务 | 缺陷处置、紧急修复的分支同步、负责人、期限、完成标准及检查时点 |
| 复盘与度量 | 周期、等待、返工、质量、人工投入、AI 用量 / 费用及缺失数据；改进措施与检查时间 |

## 3. 已填写示例：普通低风险修改

以下是一个完整虚构记录，展示各环节如何相互引用。`S1`、`P1`、`E1` 等是可读代号；真实记录必须替换为实际提交、完整摘要和可访问证据，不能以示例代号通过发布检查。

### 3.1 需求与验收记录 DEMO-01

| 项目 | 示例内容 |
|---|---|
| 来源 | 虚构反馈 F-01：后台列表无搜索结果时页面空白，用户无法区分“无结果”与“加载失败” |
| 类型与负责人 | 缺陷；需求及产品负责人许，技术负责人林，测试负责人陈，发布负责人赵 |
| 目标与范围 | 仅为空搜索结果显示“未找到结果，请调整筛选条件”；保留既有错误提示及加载状态 |
| 非目标与风险 | 不改变搜索接口、权限、查询规则、数据结构；按此范围判断低风险，范围扩大则重新判断 |
| 当前约定 | 需求 r1、计划 p1；示例第 1 日 09:00 由许确认，林安排当日 09:30 开工，在制数量由 2 增至 3 |
| 验收 AC-1 | 成功返回空数组时显示约定提示，不显示错误提示 |
| 验收 AC-2 | 请求失败仍显示原错误提示，加载期间不提前显示空结果 |
| 验收 AC-3 | 非空列表展示与搜索操作不变，提示可由辅助技术读取 |
| 交付终点与知识义务 | 实际用户可见且必要生产检查通过；发布说明须更新，技术及运维文档经林检查无变化 |
| 未知与依赖 | 开工前已核实现有组件区分加载、成功和失败；无跨需求依赖 |

### 3.2 任务、授权与中断接续

任务 T-01：在示例仓库的列表组件和对应测试中实现 AC-1–3，更新发布说明；代码基线为提交 S0、开发分支 `demo/empty-state`。林确认方案并授予本任务本地编辑、测试权限，有效至本任务结束或范围变化，可在任务记录中撤销；合并和部署另由有权人员执行。预算为 2 小时主动处理、最多 2 次失败修复循环。

示例 10:00 中断记录：实现与发布说明已保存为提交 S1；无未提交差异；AC-1、AC-2 自检报告 E1 通过，AC-3 尚未检查。当前需求 r1、计划 p1，剩余预算 90 分钟；下一步由开发者陈晨接续 AC-3 检查并核对发布说明，之后进入独立评价。

示例 10:15 接续记录：陈晨核对实际工作区为 S1、无额外差异，需求、计划和授权仍有效，继续执行。10:45 完成自检并进入评价队列。若实际发现他人已修改组件接口，应先记录差异并更新验证安排，不直接覆盖或复用 E1。

### 3.3 自检、独立评价与集成交接

| 项目 | 自检与独立评价的示例记录 | 结论与接续 |
|---|---|---|
| AC-1、AC-2 | E1 为组件测试原始结果；独立 AI 会话 V-01 读取需求 r1、代码 S1、原始报告，重新检查成功、失败及加载分支，形成 E2 | 示例预期通过，范围限 S1 与记录的测试条件 |
| AC-3 | E3 为非空列表及辅助技术检查；V-01 复查渲染结构和对应测试，单独写出结论 | 示例预期通过；真实体验验收仍由许承担 |
| 联合页面 | 需要整体布局，尚未验证；组件检查未发现阻止安全集成的问题 | 待验证，陈负责在 N3 隔离预览环境检查，不提前标为通过 |

V-01 未继承实现会话推理，结论依据不是执行者汇报；这里不因使用 AI 就免除实际证据。示例 11:30 开始独立评价，12:00 评价完成，有权开发者将 S1 合入 feature 的固定快照 I1。

N3 记录：I1 构建成功，必要基本运行检查通过；陈在隔离预览环境完成联合布局检查，形成 E4。按本批低风险判断不提前部署共享测试环境；赵依据相关负责人判断，于 12:30 同意从 I1 切出 release 候选 R1，实际范围仅 DEMO-01。

### 3.4 发布与逐条交付

| 项目 | 示例记录 |
|---|---|
| 制品及环境 | R1 的制品 P1，完整摘要记入真实记录；配置 C1、开关不变、数据库结构 D1、无迁移；测试数据集 T1 可重建 |
| 测试环境与验收 | 12:30–13:00 在共享测试环境核对 P1、C1、D1 并验证 AC-1–3；许确认本条验收及产品范围，陈说明覆盖与无阻断缺口 |
| 发布决定 | 赵批准 P1 于当日 14:00 部署生产；按实际影响检查已说明的生产配置差异；内容或授权条件改变需重新核验 |
| 恢复准备 | 恢复负责人林；确认 P0 与 C1、D1 兼容。授权边界为必要时恢复 P0，不含生产数据变更 |
| 生产检查 | 核对实际 P1、运行健康、空 / 非空列表与错误状态；出现相关错误增长或关键操作不可用时触发获准恢复 |
| 观察窗口 | 14:00–14:30；本例即时页面行为可在窗口内覆盖，无定时任务依赖。该时长仅适用于本示例 |
| 实际结果 | 虚构结果：即时检查及观察均通过；14:30 赵确认共享环境可释放，发布说明已更新 |
| 完成确认 | 15:00 许确认 DEMO-01 交付及知识义务完成；长期效果观察不阻塞此结论 |
| 轻量复盘 | 11:30 才获得评价资源，等待 45 分钟；决定下一批在开工时预约评价容量，由林在下一批复盘检查效果 |

示例度量：09:30 开工至 15:00 完成，日历周期 5 小时 30 分钟；中断等待 15 分钟、评价排队 45 分钟、待发布 60 分钟、完成确认等待 30 分钟，等待区间不重叠，合计 2 小时 30 分钟。其余为执行、验证或观察经过时间，不等于人工工时。首次必要评价后返工 0 次；人工投入示例合计 1.5 人时；AI 费用未采集，记为未知。真实试运行须替换全部示例结果。

## 4. 三个真实演练场景

三个场景当前都未执行。团队选取实际记录后，逐步写出当时依据、责任人、决定和下一步；不存在的证据记为缺口，不能按本页的预期结果填写“已通过”。桌面推演能发现流程遗漏，不能替代代码、环境或生产验证。

| 场景 | 初始条件与注入事件 | 必须作出的处理 | 演练成功标准 |
|---|---|---|---|
| A 普通低风险修改 | 按第 3 节选一条实际缺陷，中途换人或换 AI 会话 | 使用常规授权、核对接续基线、独立评价；按风险选择 N3 环境，完成批次发布与逐条确认 | 后续人员能从记录恢复工作；每个结论有适用对象和真实依据；不重复申请仍有效的授权 |
| B 依赖需求延期 | A 是导出入口，依赖 B 的导出能力；二者已合入 feature，B 在 N4 无法按期达标，另有独立需求 C | 画清 A→B 依赖；不能只移除 B 仍发布依赖它的 A。共同延期 A、B，或经需求负责人确认新的独立范围；实际剔除并重建、回归、重新核验授权后，才决定 C 能否单独发布 | 候选实际内容与清单一致；延期记录保留身份；无法安全剔除时终止该候选，不强行发布 C |
| C 下一批验证中发生生产紧急故障 | 生产 P0，feature 已重构为 F2；下一批 R2 正在共享环境验证且已迁移测试数据库 | 固定生产来源建立修复候选 H1；先保存 R2 的制品、配置及数据恢复依据，检查 P0 对应数据兼容性，安全恢复或使用隔离环境；H1 先测试后获批晋升生产；安排向 F2 和受影响 R2 的同步、故障回归及必要重验 | 生产修复不被 F2 适配阻塞；不在不兼容结构上测试旧代码；R2 恢复后含有效修复，验证及授权适用；同步义务未完成不关闭修复记录 |

场景 C 同时记录优先级与容量调整：哪条被暂停、释放或继续占用哪些资源、何时检查恢复、紧急任务由谁协调。用等效修复同步 F2 时验证故障场景，不要求与 H1 保持同一提交。

在场景 B、C 中另外检查以下环境分支：

| 分支 | 预期处理 |
|---|---|
| 取消候选但尚未操作生产 | 核实生产未受影响，发布负责人记录终止；完成环境交接即可释放，不伪造生产恢复动作 |
| 已影响生产后终止 | 先按授权完成必要恢复及验证，再释放；结果未知先查询实际状态 |
| 生产即时检查通过，需等次日定时任务 | 若保留环境，则记录下一批等待；若提前释放，须已有独立验证环境或验证过的按需重建能力、恢复时限及冲突安排；生产验证仍待观察 |
| 下一批数据库已不兼容旧版 | 使用经过验证的恢复方案或隔离环境；仅重新部署旧制品不构成环境恢复 |

## 5. 度量与演练记录口径

| 指标 | 最小记录口径 |
|---|---|
| 交付周期 | 从获准开工到需求负责人确认完成的日历经过时间，暂停时段保留并标注；另记录入至开工的排队时间 |
| 等待 | 记录开始、结束、原因及阻塞环节；重叠等待计算总时长时取时间区间并集，分类时可多标签但不重复累加 |
| 返工 | 首次必要评价后因未满足约定而重新实施的轮次和原因；正常实现迭代与新增需求修订分开记录 |
| 质量与恢复 | 交付后发现的相关缺陷、影响、恢复用时及仍未知事项；小样本保留个案，不只比较比例 |
| 人工投入 | 各参与者实际主动工作时间之和，人与 AI 同时工作不能用经过时间代替人时 |
| AI 用量与费用 | 按可取得的任务或运行记录汇总，说明共享费用分摊方式；不可取得时记未知；转换统一成本时注明费率和估算方法 |
| 未交付工作 | 暂停、延期、取消、终止的数量、已耗时间、原因及后续安排，与已交付样本一起呈现 |

每次实际演练填写：日期、参与者与职责、真实需求链接、使用的基线版本、各步骤事实与证据、发现的问题、改进负责人和下次检查时间。对比相近风险与复杂度的工作，先找等待和返工来源，不用 AI 代码占比、文档数量或自动批准率评价成功。

| 演练 | 当前状态 | 实际记录 / 证据 | 下一步 |
|---|---|---|---|
| A 普通低风险修改 | 未执行 | 尚无 | 团队指定参与者和真实缺陷，填写团队约定及执行记录 |
| B 依赖需求延期 | 未执行 | 尚无 | 选择有明确依赖的工作及独立候选，推演剔除和终止路径 |
| C 紧急生产修复 | 未执行 | 尚无 | 选择历史故障或获准演练场景，核对基线、数据恢复和同步路径 |

演练发现规则问题时更新流程基线及相关配套材料，并在决策账本保留原因；不以填写本模板代替必要判断，也不据此启动未经授权的功能开发或生产操作。
