# CimiLoop 原 Task 累计期限与宿主接续 v0.1

2026-10-08，D-230，V1-09 续批。承接[执行准备与取消监督](CimiLoop-执行准备与取消监督-v0.1.md)。本批把私有 Runtime 组合的期限绑定到原生 Task 的累计起始时间，增加同机器、同一次 Windows 启动下的持久时钟锚点。默认正式 Agent 入口仍未安装，完整 Runtime 生命周期及 S1 尚未完成。

## 原生事实与持久锚点

`openLocalAgentRunBudget` 从原 Store 读取 Run、RunRecord、Context、Task、WorkItem 和执行者。核对原 Agent 身份、当前活动 Run / WorkItem、定义 / Contract / Plan 引用，以及取消、结清和状态。首次起始依据采用内核预约时保存的 `Task.usage.first_started_at`，上限来自当前批准 WorkItem 的 `budget.max_elapsed_ms`。此接口不产生 Provider 资格或启动许可；实际工具权限仍由 Kernel 查询。

锚点按 Project / Task 保存，固定首次起始时间、原 OS 时钟观测和推算的启动毫秒位置，不按新 Run 或 WorkItem 创建新起点。首次占用目录后只写一次并同步原文件；已有目录缺少完整锚点、文件无效或原起始时间改变时拒绝，不能用重试覆盖丢失的原记录。新 WorkItem 可以使用其当前批准的上限，但已经经过的时间仍从同一 Task 起点计算。

私有只读 `AgentRunClock.cs` 由宿主编译并固定摘要，核对后运行。读取 WMI 的 `LastBootUpTime`、原生 `GetTickCount64` 与当前 UTC；机器标识只输出摘要。Windows 的[启动时间属性](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-operatingsystem)提供启动环境依据；[中断时间文档](https://learn.microsoft.com/en-us/windows/win32/sysinfo/interrupt-time)说明该启动计数包含休眠时间。此辅助程序没有文件效果、进程控制或模型凭据入口，没有修改既有四个公共原生控制器。

剩余时间取原 UTC 起始时间和固定启动计数起始位置两种已耗时间的较大值，再扣除本次时钟查询耗时。首次绑定后的墙上时钟回拨不能延长启动计数期限；机器摘要、启动时间变化或计数倒退均拒绝。异步时钟查询前后重读原生活动范围，并核对原锚点未变化。

## 执行中的停止

私有 OpenCode 组合接受原预算对象，核对原 Scope 后，将调用时长取为请求上限和原 Task 剩余时间的较小值。少于原控制器最小可接受的 1000ms 时拒绝启动，不能向上取整续期。

执行仍使用 D-229 的同一调用期限；附加不重叠的一秒预算观察，读取当前原生取消与范围、实际 OS 时钟和原文件。观察失败或当前 Run 请求取消时停止原调用，保留第一原因。结束时移除观察并取消尚未完成的时钟查询。取消继续经原控制器持有的 Job、IPC 和嵌套检查宿主传递，不按进程名清理。

原 Task 的绝对启动计数期限同时进入私有启动配置 2.0.0，由原控制器在准备、恢复前和运行中独立检查。宿主 JavaScript 线程延迟时，原控制器仍按该期限终止已持有的 Job，不重新从 Runtime 恢复时开始累计。清理记录增加实际原进程退出后的 `runtime_stopped_uptime_ms`，区分执行停止时刻与宿主返回 / IPC 清理耗时。私有恢复入口兼容原配置 1.0.0，并固定核对配置 2.0.0 与原登记摘要；旧配置不补造累计期限。

原生运行检查约每 50ms 轮询，进程终止和退出确认仍有调度延迟；实际测试对停止计数使用 2000ms 裕量，并保留宿主线程停顿场景。这是本批实际停止验证范围，完整资源 / 费用硬上限仍需后续验收。

期限耗尽或取消不自动结清 Run、返还预算或完成 Task。资源处置和结果证明继续分开：原清理记录可证明已释放本次资源，缺少完整结果仍保留未完成 / Unknown。

## 验证与边界

合同测试覆盖同 Task 换 Run、较小 WorkItem 上限、墙上时钟回拨、到期、机器 / 启动来源变化、原记录缺失 / 改写，以及异步期间范围变化。Windows 集成测试使用实际时间生成原生 Run 预约，读取真实启动时钟，在独立宿主进程重开同一原锚点，并验证原生取消停止映射后的准备。

累计期限场景给新宿主请求 90000ms，但原 WorkItem 批准 60000ms；实际 OpenCode SDK 请求进入一个等待回复的受控测试回调，在到期前有意阻塞本测试宿主 6 秒，核对原生停止计数没有超过原期限和原 Task 用量未自动变化。该回调不执行文件效果、不产生成功回执。独立宿主场景复制已核对的原预算输入，独立读取原锚点和 OS 时钟；它不声称在子进程中重新核验完整原生授权。

首轮取消命令名错误、准备回调先触发原控制器 10 秒等待上限、SDK 原始 ID 与派生工具身份的断言错误，以及错误原因被后续原控制器退出覆盖的失败均保留。后一项已修复；进一步回归发现宿主返回延迟与固定检查期限失败，促成本批增加原生绝对期限和实际停止时刻验证。最终验证范围见[D-230 工程记录](../research/CimiLoop-原Task累计期限与宿主接续-2026-10-08.json)。模型回复、受控 Provider 资格及完整保管链仍是明确构造的测试输入，不计为真实模型或正式执行验收。
