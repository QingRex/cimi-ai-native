## 启动和项目边界

要求 Node.js 24.15+、pnpm 12.4.2。先按 [CLI 操作说明](CimiLoop-CLI动作查询与诊断-v0.1.md) 初始化项目、登记责任并完成所需配置，再从此仓库启动：

```text
npx pnpm@12.4.2 install
npx pnpm@12.4.2 build
npx pnpm@12.4.2 workbench --project-dir <已初始化项目目录>
```

服务默认绑定 `127.0.0.1` 随机端口并打开默认浏览器。可加 `--port 11277` 固定端口；Ctrl+C 停止服务。启动器仅输出普通地址，不输出一次性登录片段、会话或 CSRF 凭据。普通地址本身不能建立新会话；关闭服务或会话到期后须重新启动并使用启动器打开的浏览器。

服务在启动时固定项目、数据库及初始化的本地 Human Actor。实例、Project、仓库物理目录及 Actor 类型必须相符；HTTP 请求不能指定 Actor、Project、调用来源、数据库或文件路径。现有 Git 项目仍使用 Git Common Directory 下的项目数据，非 Git 项目使用 `.cimiloop`。另一物理 worktree 的入口不会自动借用原项目身份；正式 Runtime 工作区须经自己的受控入口。服务不自动初始化或迁移项目库。

## 已接通的页面和动作

| 页面 | 当前能力 |
|---|---|
| 项目工作台 | 实际需求数量、在制容量、暂停、任务满足及 Provider 准入缺口 |
| 需求池与版本 | 读取全部需求 / 缺陷与目标版本，录入需求 / 缺陷，按 `flow_owner` 创建目标版本 |
| 需求详情 | 正式约定 / 计划、候选、任务 / 授权 / 用量 / 运行、证据 / 评价及交接事实；暂停 / 恢复、初始化计划任务、有计划后的开工、源码快照、取消运行和保存交接 |
| 决定收件箱 | 固定候选内容、专业风险、期限、角色与输入摘要；记录约定 / 计划的批准、要求修改或拒绝；另行应用已批准决定 |
| 发布批次、环境 | 明确显示尚未实施；真实操作按 S2–S4 接通 |

约定简表仅支持一项验收、无知识影响、`other` 风险类别的候选。复杂约定、完整 Plan、专业原始报告导入、条件核验、授权及独立评价仍通过已有 CLI 操作，然后刷新页面读取同一原生事实。专业决定不能用普通候选表单代替。

仅确认约定的 `IntentReady` 显示“约定已确认”；有正式计划才提供开工入口。按钮不作为授权证明；每次命令仍由 Kernel 核对实际角色、精确引用、当前版本、输入摘要及预算。记录批准和应用批准是两个动作，附带条件未满足时应用仍被拒绝。未知费用不显示为零。

每次 Kernel 查询保留其原生事实序号。工作台汇总多个查询，不能把整页称为同一个原子快照；页面停留期间事实可能变化，提交发生冲突时显示当前版本和缺项，刷新后核对。

## 本地会话与数据保护

一次性随机登录片段只用于换取八小时的 HttpOnly、SameSite=Strict 会话 Cookie，页面随即清除片段。CSRF 随机值只保存在页面内存。Host 必须为当前回环地址，写请求要求精确 Origin 和独立 CSRF；外来 Origin、跨站读取、重复保护头与过期会话被拒绝，无 CORS 放行。

请求仅接受严格 JSON，限 128 KiB；响应限 4 MiB。服务不提供任意 SQL、文件读取、身份切换或初始化 / 迁移端点。页面使用文本节点显示外来内容，并设置 CSP、禁止框架嵌入、禁止缓存和无 Referer。HTML / JS / CSS 在启动时读入内存固定，修改源文件后须重启工作台，不会把正在运行的操作页面热替换为新源码。

这不是同一 Windows 用户下恶意程序的隔离证明，也不是 Agent 权限入口。正式 Agent 的 OS 隔离、身份、费用、工具效果及恢复继续按 [Runtime 实施边界](CimiLoop-WorkItem工具授权与执行账本-v0.1.md) 验收。

## 响应丢失与接续

页面发送前生成一次 `command_id` 和 `requested_at`，将完整待核对请求保存在当前标签页的 `sessionStorage`；其中不保存登录 Cookie 或 CSRF。会话存储不可用时拒绝发送。网络中断、服务端错误或过大响应留下原请求，阻止继续写入，并提供“按原请求核对”。同源刷新后仍读回原请求，用相同 ID、时间和内容查验原生回执；不生成新 ID 重做动作。

收到确定成功后先清除待核对请求，再刷新查询。刷新失败显示“动作已记录，但刷新失败”，不会把已提交动作重新归为未知。确定的原生拒绝清除待请求，允许核对当前事实后重新准备动作；会话过期等传输拒绝不能证明此前没有提交，仍保留原请求。

服务关闭使旧会话和 CSRF 失效，但数据库回执保留。固定端口重启可保持相同浏览器 origin；随机端口变化不会自动迁移原标签页的 `sessionStorage`，应保留原请求并经受信入口查验。页面记录的交接可以从 CLI 查询和继续准备接续，累计尝试与未知用量保持原生语义。
