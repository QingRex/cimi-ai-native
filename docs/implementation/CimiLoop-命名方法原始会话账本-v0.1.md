## 本次补齐的证明

[D-217 的转录重放](CimiLoop-命名方法资格规则与原始效果重放-v0.1.md)可以核对已解析回复和实际 SDK 读取，但无法独立复算 `response_digest`。D-218 将公开命名演练切换到独立 GatewayCreditLedger 格式 4，保存完整规范化输入、实际 HTTP 请求正文和响应正文，与格式 3 的最小工具契约及已解析缓存分别存储。

响应正文是严格 HTTP / TLS 边界接收、完成 EOF 并通过 JSON / SSE 解析后的原始字节，包括 SSE 事件和结束标记；没有重新序列化后冒充原文。读取时重新生成请求正文并复算摘要，再从响应正文重新解析结果，核对缓存、原请求和完成回执的摘要及用量。

这里只保存 HTTP 正文字节，不保存 TLS 会话或 HTTP 原始报文头；也没有由此获得真实外部服务来源证明。公开演练的连接、证书和响应仍是测试装置。

## 格式与事务边界

格式 1 / 2 / 3 的 Schema、隐私范围和原方法保持。格式 4 必须显式选择 `conversation_original_cache`，固定原操作键和完整方法 Profile 摘要；相互打开不同格式会拒绝，没有隐式升级。原生项目数据库仍是格式 10，没有变更布局、增加迁移或升级用户库。

格式 3 继续只保存最小契约与解析结果，不保存提示词、工具结果或推理原文。格式 4 明确保存公开会话全文，仅使用宿主代码中固定的公共测试 Key；不能传入真实 Key，也不能通过配置声明外部模型来源。请求中的 Key 在费用预约和输入持久化之前检查，拒绝的响应不写入原响应表。

每次请求在发起 HTTP 前提交原预约 / 输入 / 请求正文，完成时在同一个 SQLite 事务中保存原响应正文、解析结果和完成回执。完成前失败或进程退出留下原调用 Unknown 与完整费用占用，不发起新调用；完成后的重放从原响应重新验证缓存，不再解析 DNS、建立连接或发送 HTTP。

原输入和请求正文不可修改，响应正文只允许从空值写入一次；格式 4 有独立的不可删除 / 不可改写触发器，并继续在事务中核对完整 Schema、策略、外键、记录、摘要和容量。触发器和摘要不构成防御本机同权限用户改写整个数据库的安全边界；生产保护和账户唯一性仍须实现。

输入最多 98,304 字节，请求正文最多 65,536 字节，原响应正文最多 262,144 字节。一个预留槽还包含最小契约和解析回复的既有上界，共 761,856 字节。容量以实际存储字节加未完成响应上界核算；Unknown 保留原响应槽占用和永久条目，不能通过失败回收槽位绕过上限。此处是逻辑内容容量，不是 SQLite 文件 / WAL 或工作区物理硬配额。

## 具体读取器与命名资格

`openPublicNamedMethodOriginals` 只读打开已存在的格式 4 数据库；不存在的数据库不会被创建，策略及原操作 / Profile 必须匹配。读取器从首次 SDK 请求重放完整方法，再在一份数据库快照中读取全部原会话，核对每个投影请求、正文、已解析响应和完成回执，拒绝遗漏、额外请求、未完成状态或移植的调用身份。

`LocalPublicNamedMethodOriginals` 将这个实际读取器接入命名方法资格评测，重新读取原输入 / 包 / 转录。它的来源恒为 `public_fixture`，返回的原请求 / 响应摘要及回执参与本地评测摘要；导入 JSON 的来源标签或 ALLOW 字段不能取代读取。

即使读契约及全部原 HTTP 字节一致，公开来源在 `controlled_execution` 中仍得到 DENY。SDK / Native 日志的生产保管链、独立上下文、依赖、权限、真实套餐 / 账单、效果恢复、方法行为和声明的 harness 均未由这个读取器证明，保持缺项。默认本地 Human 应用没有安装生产 Agent / Skill 宿主，正式执行保持关闭。
