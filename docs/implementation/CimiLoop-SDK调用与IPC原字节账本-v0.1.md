## 原字节先于执行与发送

独立账本位于可信宿主资料目录，按 Project / Run / 原管道 nonce 定位。原生管道核对原控制器和 Runtime 的 PID、创建时间、程序路径及 AppContainer SID 后，宿主独占创建账本，保存完整原 Scope、原 endpoint、原传输程序摘要和容量规则；没有覆盖或重新创建原账本接口。

原生传输核对每份请求的原字节摘要后，宿主先保存 `request.raw` 及摘要记录并同步文件，再进入权限 / 工具回调。响应原字节及摘要先保存并同步，再发送给原管道。仅记录 `reply_recorded`，不声称响应送达、SDK 收到、Task 成功或费用结清。真正发生的文件 / 检查效果仍由原工具账本和回执证明；本批不替代该账本。

单份请求 / 响应最多 114688 字节，每份原账本最多 128 次交换。这个有限容量不是物理磁盘硬配额。原字节写入中断、响应丢失或半份记录保持未知，已有字节保留；序号缺口、Scope / 原身份不符、原摘要损坏和重复写入拒绝，不补写成功。没有原登记的历史管道保持 Unknown，损坏的原登记不能取得有效资料结论。

## SDK 对应关系与原操作采集

只读读取器核对原账本头、交换顺序、准确原字节、请求与响应摘要关系，区分完整响应记录与缺响应。SDK 对应核对读取实际 stdout 中的 session / message / call 身份，重新计算原 `sdk_` ID，逐项比较 SDK 工具名、实际入参和输出投影与原 IPC 请求 / 响应。固定检查的 passed / failed 与原回执、源码、输出摘要一致；记录成功不能把 failed 改为 passed。

`collectAgentRuntimeOperation` 使用原配置的管道 nonce，重新核对账本中的原控制器、Runtime 与 SID 和原启动证明。原账本头、请求、响应及摘要记录逐份形成原字节引用；SDK 核对使用本次实际采集的 stdout 字节。运行中采集可能不完整，不能声称所有资料来自同一个完成时刻。

SDK 流截断或 UTF-8 / JSON 无效时仍保留已经取得的原始字节，返回未确认诊断，不伪造对应关系。`model_account_custody_proven: false`、`native_effect_reverified: false` 和 `formal_agent_execution_enabled: false` 保持：本批核对 SDK 与 IPC 的字节关系，没有完成 Provider / 模型 / 账户资格、原 Native 回执独立再验或领域 RunObservation。
