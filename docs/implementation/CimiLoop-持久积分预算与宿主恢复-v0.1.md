# CimiLoop 持久积分预算与宿主恢复 v0.1

2026-10-05，V1-09续批，决策D-202。新增独立持久积分演练账本、共享账户累计上限、任务标签上限、不可复制的发送凭据、完成回执及原宿主身份核验后的保守恢复。已实际验证双宿主争抢同一账户额度和另一宿主提交发送状态后退出。这里仍是预算演练：不确认真实账户、订阅资格、服务端Token边界、实际费用或正式执行准入，没有发送HTTP、读取真实Key、启动模型Runtime或升级用户库。

## 1. 独立积分账本与累计上限

积分单位固定`ZHIPU_CODING_PLAN_CREDIT`，一积分为1000000微单位，预算及预留向上取整至整积分。SQLite使用独立application_id=`0x43494d43`、格式1、STRICT表、WAL、synchronous=FULL和BEGIN IMMEDIATE。原TEST账本的application_id=`0x43494d47`及格式1保持，领域数据库仍8；拒绝外来库、旧TEST账本、缺失 / 多余的Schema或损坏数据，不自动转换或修复。

账户策略固定格式、scope=`credit_budget_rehearsal`、账户范围摘要、单位、模型GLM-5.3及累计演练上限。首次建立后不能通过重新打开提高上限或换账户；调用者的数据先复制并冻结。每个任务标签另登记不可变上限，且不能超过账户上限；不同任务的预留在同一账户事务中求和，防止逐任务都通过但合计超支。最多4096个请求，未完成、完成及Unknown都计入累计持有量。

本批账户摘要来自合成标签，不读取或散列真实Key，不代表已核实实际账户。`task_a`、`task_b`是演练预算标签，没有绑定正式Task、WorkItem或现金TaskUsage。预算是本地累计上限，没有自动5小时 / 每周刷新、额度释放、缓存 / 活动折扣或积分换现金；真实套餐窗口、余额、账单和任务现金预算的关系仍须另行设计并验收。

同一实际账户未来必须定位到一个可信、受保护的共享账本。当前类型不允许把多个任意文件各自的账户上限相加当作整体控制；目录、账户范围及凭据引用的可信绑定尚未批准。单个SQLite文件的并发不超支证明不能替代这个绑定。

## 2. 请求身份、预留与一次发送

请求ID在整份账户账本中唯一，绑定预算标签、输入摘要及输入 / 输出Token上界。新请求通过数据核验、账户及任务累计上限、公开费率观察有效期后，在同一事务中登记宿主和预留。Token数量只作演练条件，不宣称已证明真实Tokenizer或包含思考的生成上界；费率依据及限制延续[D-201公网网关边界与积分估算](CimiLoop-公网网关边界与积分估算-v0.1.md)。

预留返回原Ledger实例用WeakMap登记的冻结凭据。复制对象、从JSON恢复、转交另一实例或只给请求ID都不能领取发送权。`dispatch`先核对原预留、宿主nonce、状态、账户未封锁及当时费率仍有效，再提交`dispatching`；调用者只有在提交成功后才可进入后续发送层。本批没有发送层，这个状态不能当作网络授权。

同一请求不能再次发送。重启或另一实例看到reserved / dispatching / unknown时返回`credit_request_outcome_unproven`；完成请求只能读取经过摘要和语义核验的回执，不得到新的发送凭据。同一ID改变标签、输入摘要或Token边界返回冲突。回执只保存响应摘要与演练用量，不保存提示、凭据或完整响应，也不能替代未来真实网关的受限响应缓存。

真实HTTPS接管仍需D-201的一次地址固定、TLS / 对端核验、请求取消 / 时限、完整响应和思考用量约束，再把完成响应及持久缓存与本账本状态对齐。尚未连接这条路径。

## 3. 完成、到期、取消及宿主恢复

有效完成只从dispatching进入completed；相同完成数据可重复读取，矛盾完成拒绝。完成仍持有全部预留，较低观测用量不等于可靠账单，不退款。恶意 / 异常用量超过原输入或输出边界时，将该请求记为Unknown并封锁整份账户，保留原持有量，拒绝后续新请求；这不证明真实费用仍在原界内，因此真实执行必须先有服务端边界及计费证明。

新预留和新的dispatch都检查费率观察有效期。费率到期后，历史持有量、完成回执及恢复仍可读取；已经进入dispatching的迟到完成按原保存的费率观察与边界核验，不能改用新费率减少旧持有量。每个请求保存原费率观察、来源及摘要；没有把恢复变成重新计价或重新发送。

显式取消保留原预留并进入Unknown。Ledger关闭只将本实例nonce拥有的未完成请求记为Unknown，再释放连接；不改变其他活跃Ledger的请求，也不自动返还尚未发送的预留。

崩溃可能留下reserved / dispatching。独立原生只读查询在同一个OS进程句柄上核对PID、创建时间、程序路径及存活状态。只有原宿主确认absent后，才在事务中重新核对保存的宿主身份摘要，把该宿主未完成请求记为Unknown；不会调用按PID杀进程、重发请求、删工作区或宣称AppContainer已释放。active拒绝恢复，unknown、访问失败或读取异常保持原状态与预留。Windows退出后可短暂显示unknown，调用者只能有界重复核验，不能按等待时间推定已结束。

本批每个宿主即实际Ledger写入进程，未创建AppContainer、Job、Runtime会话或网络请求。正式受控执行恢复仍需分别覆盖原Runtime、网关、监督进程和原隔离资源，不能用本地积分账本恢复替代。

## 4. CLI、格式与演练范围

```powershell
pnpm cimiloop --json runtime gateway-credit-probe `
  --output-dir '<持久积分预算演练目录>'
```

目前此实测入口要求Windows x64，以核验实际OS宿主。只接受输出目录，不接受真实连接、Key、端点、Runtime二进制、费率、额度或approved覆盖。每次保存独立`runs/<UUID>/`及内容寻址观测，根目录只保留最新结果。通过退出0、演练未通过退出1、参数错误退出2；0只代表这些预算与恢复条件通过。

探针使用固定2026-10-05T00:00:00Z作为历史演练时间，明确`historical_rehearsal=true`。这样日后仍能复现这组记录，不会因当前网页费率到期而把历史测试误当当前计费授权。真实Ledger默认使用当前时间，新预留及dispatch在观察窗口外拒绝；CLI不能指定日期来绕过实际准入。

新增独立严格v2格式`RuntimeGatewayCreditSnapshot`、`RuntimeGatewayCreditProbeResult`。记录累计持有量、任务上限、四种状态、封锁、检查项、原宿主核对、实际独立宿主数量及有日期的费率观察。解析器核验预算守恒、最小整积分持有量、状态计数、标签唯一和完整检查清单。`actual_cost_known`、`billing_admission_ready`、账户版本 / Token边界证明、正式执行均固定false；HTTP、模型与真实Key读取固定0。

`requireDedicatedGatewayBilling`仍在Key解密、真实请求账本或DNS前拒绝，`assessDedicatedGatewayBilling`的已批准持久预算缺项没有因这份演练自动消失。旧Runtime / D-198–201格式、冻结v1、领域8、TEST账本1保持；未升级用户库。

## 5. 验证与下一步

实际CLI的15项检查覆盖共享账户上限、不可变任务上限、跨任务请求身份、完成回执、不可复制的发送凭据、取消持有量、活跃 / 未知宿主拒绝恢复、费率到期的新发送拒绝、历史完成可读、超界封锁、双宿主CAS、第三宿主退出后的恢复、真实计费准入关闭及旧TEST账本拒绝。

实测3个独立子宿主（主CLI宿主另负责单进程案例）：两个对同一累计上限争抢，只有一个预留成功；第三个提交dispatching后以73退出，原身份确认结束，恢复为Unknown且预留不减，再次请求拒绝。原生辅助查询不计作积分账本写入宿主，也没有启动模型Runtime。专项5个文件89项通过，补充异常完成数据回归后最终全量40个文件436项通过，本批新增25项回归。

固定Node24.15.0 / pnpm12.4.2的类型检查和Schema导出通过，原RuntimeOperationResult / RuntimeProbeResult及D-201网络格式摘要保持，冻结v1兼容测试通过。两次保留CLI演练的14份积分库均核验为completed / unknown且无reserved / dispatching残留；6个不同的已存原写入进程身份确认absent。原TEST库的application_id及格式保持。源码与窄原始观测均归档，不归档实际SQLite内容或凭据。

初验修复了原生辅助命令的局部变量命名冲突，以及损坏数据夹具先被SQLite外键阻止的问题；只在测试故障注入中关闭外键，正式Ledger继续核验外键。另一次退出宿主最初返回unknown，保留原状态后有界复核至absent，未按退出事件或时间推定可恢复。最后补上非字符串摘要及额外完成字段的拒绝回归，保证异常完成不会污染持久回执或改变dispatching；原失败日志保留。

原始观察与源码字节另存内容寻址归档，研究摘要见[持久积分预算与宿主恢复实测](../research/CimiLoop-持久积分预算与宿主恢复-2026-10-05.json)。演练文件只属于本批，未读取真实Key、修改实际套餐、扣真实积分或迁移用户项目。
