# CimiLoop 生产执行期限与原 Task 组合 v0.1

## 可执行变化

共享正式组合不再借用演练的固定180秒上限。生产执行选用代码固定的 `agent_task/1.0.0` 策略，最多一小时，并取原 Task 累计剩余时间与该上限的较小值。调用方指定更短期限仍受同样约束；缺原 Task 预算、到期、非法数值或未知策略均拒绝。

旧文件 / 检查演练的默认45秒和最多180秒保持。原 Task 首次开始时间、机器 / 启动身份、持久时钟锚点及 Native 绝对 uptime 期限没有重置；准备阶段已经用掉的时间继续扣除。原 Run / operation_key 唯一启动账本和 Kernel 启动检查保持，响应丢失只能核对原操作。

共享应用服务的模型资格检查、检查目录安装、资料组装及模型 header 初始化都纳入原 Task 剩余期限和取消监督。资格回调迟到返回不能创建新 header 或放行；迟到服务资源关闭。进入 Native 引擎后重新核对原剩余期限，所有准备阶段的资格回调与最后放行也受同一原运行期限和取消信号约束。

新生产 Native 配置为私有 `cimiloop/agent-workspace-sandbox-config/4.0.0`，明确固定 `lifetime_policy: agent_task/1.0.0`、原任务资料和原绝对期限。Native、原操作读取 / 恢复和负面结果核验均显式支持该格式；未知策略不被采纳。

格式1、2、3按各自原字段集合解释，最多180秒；格式4最多一小时。旧配置、旧原请求、旧失败证明和 Unknown 报告不会重写或自动改变语义。242公开Schema与用户项目数据库格式10保持，没有迁移用户库或修改锁文件。

本批不改变真实模型账户准入、账单与领域终态要求。实际模型调用仍通过受信宿主端口，默认端口未安装时拒绝。Native / SDK / 工具成功事实本身不能形成 Task 满足、费用结清或 ReadyForDelivery。
