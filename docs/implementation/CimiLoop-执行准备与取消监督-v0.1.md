## 一次调用内的统一期限

原私有 OpenCode 组合先编译、复制和登记资源，随后等待 IPC 接入，再恢复原 Runtime。此前截止计时在资源准备后开始；`ready` 已完成后，截止或原进程退出不能打断一直不返回的 `connect`。宿主可能在进程结束后仍卡住，无法可靠完成停止与诊断留存。

`ExecutionLifetime` 在异步准备前创建，以单调时钟核对同一个总时长，并把取消信号传入编译 / 原身份查询、准备回调及 IPC。每个异步边界再次检查；IPC 接入和 Runtime 执行不能续期。同步的有界文件复制 / 摘要计算只能在边界处检查，本实现不声称能抢占同步 JavaScript 或提供文件系统物理硬配额。

外部停止、期限到达、恢复前原控制器退出分别保留第一原因。预先取消在分配 Runtime 操作目录前拒绝。准备回调或接入回调不合作时，宿主停止等待；回调收到同一信号，迟到的接入结果被请求关闭，不能恢复原 Runtime。迟到关闭失败不构成资源已经处置的证明。

## 原操作停止与嵌套检查

信号关闭原控制器的专用输入；原控制器使用已持有的进程 / Job 句柄停止原 Runtime，继续产生原生资源清理记录。宿主在有界退出宽限后仅终止本次创建的控制器，不按进程名或新查询到的 PID 操作其他运行。停止后保留 stdout / stderr、原登记、原退出 / 清理和 `incomplete.json` 中的 `interruption_reason`。

原 IPC 接入在异步编译后重新检查原控制器是否退出或取消；构建完成不能把已结束的原控制器重新接为可用 peer。接入服务提前捕获 nonce / signal。IPC 收到取消后关闭原文件与检查宿主；已创建的 Node 检查收到原取消文件，等待实际原生退出、回执和资源处置核验，而不是把未收到的 SDK 回复解释成通过。

有完整原生检查失败回执时保留 `failed / cancelled`；没有完整回执的已 dispatch 操作继续 Unknown，父 Run / 预算结清规则保持。停止演练不自动提交 RunObservation、返还尝试预算、满足 Task 或推进 Gate。
