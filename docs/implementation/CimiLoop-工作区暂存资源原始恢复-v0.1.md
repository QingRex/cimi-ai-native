# CimiLoop 工作区暂存资源原始恢复 v0.1

日期：2026-10-07。D-220 延续 [D-219 工作区工具宿主](CimiLoop-真实工作区工具宿主与运行恢复-v0.1.md)，处理已保存原生准备证明的私有暂存文件。正式 Agent、IPC / OpenCode、固定检查命令、技能方法宿主和完整 S1 仍未完成。

## 实际恢复入口

受信 `WorkspaceToolHost.recover()` 先核对原拥有者并恢复调用状态，再回收拥有者已经退出的原调用资源；`LocalWorkspaceToolService.recover()` 使用同一项目、原工具账本及代理。旧的 `reconcileOwners()` 保持只恢复状态的职责。没有新增 Runtime 自选路径、进程名清理、CLI 或工作台正式执行入口。

`reserved` / `executing` 仍按双拥有者实际观测处理：原 Node 宿主与已记录文件代理任一活动或无法核定时保留原状态。两者确认不存在后，未 dispatch 为 `not_started`，已 dispatch 且没有完成回执为 `unknown`。资源回收仅读取 `not_started` / `unknown` / `completed` 的原准备记录；没有保存准备证明的调用不进入回收范围。

## 删除必须匹配原身份

账本先验证策略、完整输入、原 Node 身份、原生准备证明及其摘要；查询两个原拥有者，等待返回后重新确认原记录未变化。传给恢复器的是原记录的独立副本。生产组合器安装实际 Windows 代理；构造回调只用于独立 Journal 测试。

原生恢复代理还会独立核对两个拥有者的实际 PID / 创建时刻 / 程序路径和退出状态。PID 已复用意味着原进程不存在；无法访问或无法核定时拒绝。核对创建时刻后，已发出退出信号的进程可直接确认为结束，避免对已经结束的进程强行读取程序路径。恢复过程不会终止原进程或重启工具效果。

文件位置只能由原 `worker.image` 的私有构建目录和原 `nonce` 派生，且必须属于本项目固定 `tools/workspace-<64 位源码摘要>/WorkspaceFiles.exe` 布局。不能传入工作区资源路径或任意临时文件名。恢复器持有私有根及祖先目录句柄，拒绝链接、目录置换和越界；旧构建目录或原文件确实缺失时只返回 `absent`，不会重建。

删除前打开具有 DELETE / READ_ATTRIBUTES 权限的原文件句柄，核对实际路径、普通文件类型、单一链接、卷号及原 `replacement_identity` 的 file index，再次确认两个拥有者不存在。通过同一句柄设置 `FileDispositionInfo`，关闭句柄后删除；不使用核对后按文件名删除的方式。API 权限和结构语义见 [Microsoft SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle) 与 [FILE_DISPOSITION_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_disposition_info)。

当前源代码版本可以处理同一项目旧私有构建目录中记录的原资源，不需要运行旧代理或读取其可执行文件。文件被替换、改名、增加硬链接、变成目录或越出项目私有目录时，拒绝删除并保留现有资源。没有原账本证明的文件不扫描、不按名字猜测归属。

## 资源结果不改变调用事实

返回 `owners` 状态恢复统计与 `resources` 资源统计；后者区分 `removed`、`absent`、无替换资源的 `not_applicable`、活动拥有者、无法核定拥有者及无法证明的清理。失败保留资源，允许后续重新观测；正常返回前仍须确认实际恢复代理完整退出、输出边界及原准备摘要一致。

回收不修改调用状态、完成回执、输入或永久槽位，不返还预算，不追加领域事件。重复回收重新观测同一个原资源；它已缺失只说明这个私有路径没有资源，不证明历史工具没有执行，也不能把 Unknown 改为完成。已 dispatch 的 Unknown 继续阻止父 Run 成功 / 失败 / 取消结清及不实返还。

## 验证及边界

原始报告与固定源码摘要见 [D-220 验证记录](../research/CimiLoop-工作区暂存资源原始恢复-2026-10-07.json)。实际 Windows 测试在受控临时目录中捕获真实 Node / 文件代理身份，强制终止自己创建的代理和宿主，验证匹配资源删除、重复恢复、文件身份 / 硬链接 / 类型 / 路径反例和活动宿主拒绝。另一实际编译、仅注释不同的源码构建验证跨构建目录恢复及原程序缺失的处理，不声称历史版本资格已全部验证。真实 Git / Kernel 场景分别在准备后和 dispatch 后强制退出，验证清理后调用及父 Run 事实、用量和事件序列保持。

第一轮 17 项测试中 15 项通过、2 项失败，原报告保留。一个失败来自原进程已退出而程序路径不可读的观测时序，已调整实际原生观测顺序；另一个是测试使用文件删除函数清理目录，已修正为删除已知空目录。反例测试现在先确认原拥有者确实不存在，并断言具体拒绝原因。

最终构建及类型检查通过，固定源码下受影响的 13 个测试文件共 179 项全部通过；具体报告和范围由上述验证记录固定，不据此声明整仓测试通过。没有升级用户库；原生格式 10、239 个 Protocol Schema 和原工具账本格式 / 回执保持。没有读取真实凭据或发送外部模型请求。

本批不构成完整资源清理或磁盘硬配额：在原准备证明提交前强制退出的无账本资源、暂存路径被外部改名 / 替换的资源、不能确认的原进程，以及 SQLite / WAL 物理占用均不能据此宣称已经回收。同权限 Human 对私有文件或工作区的并发干预仍在生产归属 / 保管链的后续范围。
