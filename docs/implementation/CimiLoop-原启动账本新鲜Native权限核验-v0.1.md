## 可执行改变

共享原启动账本现在使用固定 C# 宿主助手代替每次新建 PowerShell。助手仅有 identity、protect、verify 三种固定动作：identity 返回当前登录 SID 的 SHA-256；protect 只由显式新账本初始化调用；verify 逐次读取当前目录和四个 SQLite 文件的真实 ACL。没有缓存授权结果，没有改变原账本、票据或 Run claim 的身份和 CAS。

目录必须仍由当前登录主体持有，禁止继承，只保留该主体的 FullControl、ContainerInherit / ObjectInherit 规则；存在的 starts.sqlite、wal、shm、journal 必须保留原继承规则、同一主体和唯一完整控制权限。新增拒绝目录祖先或 SQLite 文件的 reparse point。原机器身份仍通过独立 Native 时钟读取，退出后关闭原时钟通道。初始化 / 打开在关闭通道后重查调用方取消。

助手按固定源码摘要构建，当前端口冻结编译产物的摘要；每次动作重读助手字节，不能通过同步改写 build.json 改变已经打开的授权实例。编译保留调用方取消和独立 30 秒期限，运行保留 15 秒期限、输出上限和返回时实际耗时检查。只有严格 64 位十六进制摘要可作为身份结果。错误不转发 argv、输出、环境、SID 或路径；找不到旧目录仍拒绝并保留原操作，不补建旧账本。

同步核验速度直接影响同一 JavaScript 线程处理 Task 时钟响应。旧实现的连续 64 次真实权限和账本检查触发了原 15 秒时钟期限反例；较少的 24 次检查实测共 9328 毫秒、单次约 344 到 501 毫秒，该次时钟仍成功，所以这项采样本身不能证明超过期限。本批替换实际共享工厂，继续用当前 ACL、SQLite 完整性和票据重核授权，而不是通过缓存或放宽期限绕过问题。

## 实际验证与未解现场

最终固定源码验证结果及每阶段原件摘要见[研究记录](../research/CimiLoop-原启动账本新鲜Native权限核验-2026-10-09.json)。实际 Windows 控制回归四文件十项通过、零跳过，包括 64 次新鲜核验、改写助手与摘要记录、SQLite 权限漂移、跨进程唯一登记、缺原账本拒绝、时钟取消及 held owner 死亡、Task 原截止和当前取消。受影响契约九文件73项通过，类型检查、CLI帮助和25文档检查通过；SDK组合两文件两项一通过一失败，零跳过，不是完整S1验收。

首次 Native 版本的三项实际回归有一项在权限助手处失败。随后只读重放记录到助手的 Windows 退出码 3221225477（0xC0000005），stdout / stderr 均为空、二进制摘要未变。独立空 .NET 程序以及显式 x64 / x86 编译也复现同码；PowerShell 启动空程序、后续异步和最小环境对照通过。最后同一空程序的两轮隔离环境和一轮最小环境各 96 次均通过，未支持环境变量归因。没有查到对应应用崩溃事件，未证明根因，也未将其归因于 ACL、杀毒软件、.NET 或旧时钟故障。

这些失效仍拒绝授权，不进行自动重试或重开 Run。最终通过不能覆盖先前失败，不能宣称本机 Native 启动稳定性已完全解决。独立只读工程评审未发现必修项；它不是正式 Matt 独立评审或 Superpowers 真实方法执行证据。
