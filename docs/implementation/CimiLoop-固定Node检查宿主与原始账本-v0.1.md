# CimiLoop 固定 Node 检查宿主与原始账本 v0.1

日期：2026-10-08，D-225，V1-09 续批。承接 [D-224 文件工具消费](CimiLoop-OpenCode工作区工具真实消费-v0.1.md)。实现真实 Node 检查宿主和原调用记录，并接入父 Run 工具核对；正式模型、SDK 检查工具、费用、物理配额、真实方法及 S1 验收仍待完成。

## 命令来自固定配置

可信 Agent 组合器一次安装检查目录。执行接口只接受 `check_id` 和可信组合器传入的 `call_id`，不能提供 shell、执行文件、参数、环境变量、cwd、来源文件内容或期限；原 SDK 调用 ID 接入仍是下一步，当前没有模型消费此接口的入口。目录固定 profile、入口、文件内容摘要和有限期限 / 输出上界；异步安装前复制原 Scope 和目录，不能用后续对象修改替换已安装配置。

首批 profile 是 `node_syntax` 和 `node_test`，支持既有 `.js` / `.mjs` / `.cjs` 入口，最多 32 个文件，每个文件沿用原文件宿主 16 KiB 上界。Node 二进制由可信组合器指定并复制到私有工具目录，运行前检查原字节摘要。测试锁定 Node 24.15.0；该 API 本身不签发二进制来源或生产宿主资格。

语法检查固定使用 `--check`；测试固定使用 `--test --test-isolation=none --test-reporter=tap --test-timeout=<已登记期限>`。版本依据见 [Node 24.15.0 CLI](https://nodejs.org/download/release/v24.15.0/docs/api/cli.html#--test-isolationmode)。单进程模式与原生 Job 的单进程限制一致，不通过提升子进程权限运行 npm、pnpm 或任意仓库脚本。

## 当前权限与实际输入

原 Kernel 对每个输入核对 `read_files`，对固定入口核对 `run_checks`。原 Run / Context / 执行者 / Runtime、Skill Binding、宿主准入引用必须一致。开始读取、逐个原文件读取后、完成输入快照后以及原 dispatch 前重新查询当前权限；依据变化或当前撤销拒绝。独立只读 Context 继续遵循现有权限规则，本批没有放宽它。

实际来源由 `WindowsWorkspaceFileBroker` 持有原文件句柄读取，核对声明摘要、文件类型和原仓库目录身份。检查仅访问私有只读快照，无网络 Capability，状态目录私有。原生 Job 原子创建、单进程和 2 GiB 内存限制沿用固定控制器；原始控制、政策及清理记录位于检查沙箱之外。

调用的成功只表达固定命令真实结束且退出 0；语法检查不证明业务行为，测试输出也不构成独立评价、Task 完成或 Gate 批准。结果保留 `formal_agent_execution_enabled: false`。

## 原调用与恢复

检查记录使用独立的私有效果目录，不改变原文件账本格式。项目策略固定原仓库 / 目录身份、Node 摘要及 128 个逻辑调用槽位。槽位独占创建后再创建原调用目录，两宿主争同一调用最多启动一次。槽位满时拒绝且不继续制造操作目录；逻辑容量不是物理磁盘硬配额。

原 Scope、调用、检查目录、权限依据和策略形成固定输入摘要。原请求先持久化，来源快照随后保存；持久 dispatch 必须先于原生进程创建。完成回执固定原调用及来源 / stdout / stderr 摘要，回放重新核对当前权限、原输入、原退出 / 清理与捕获记录。不同检查内容冲突、损坏输出或未确认结果都拒绝，不更换调用 ID 或自动重跑。

dispatch 前已确认停止可记录 `not_started`；dispatch 后没有完整原回执保持 Unknown。来源快照、原输出、原生证明和有限捕获记录可复查。截断输出不发布完成回执；它不能被最终文本或退出 0 覆盖。原文件与检查记录的计数合并进入 `readWorkspaceToolRunFacts`，检查 Unknown 同时阻断 Agent 观测与 Human 核对结清父 Run / 预算。

恢复仅查询原请求中记录的拥有者，并调用原字节固定的原生资源恢复。必须证明原拥有者和控制器 / Runtime 结束，才能移除对应 ACL、映射和 Profile。实际原宿主 / 控制器崩溃后可恢复原资源，但不推定检查结果，不重跑、不伪造完成证明。正常拥有者仍活动时拒绝外部回收。

## 实际验证与发现

实际 Windows、Node、Kernel、Git / SQLite 联调覆盖语法通过 / 失败、单进程 `node:test`、快照写入拒绝、两宿主争用及回放、原始输出损坏、权限撤销、dispatch 丢失、输出截断、容量拒绝和原宿主 / 控制器死亡后的资源恢复。正向 Agent 准入仍是明确构造的测试端口，不能把这些结果升级为生产模型或技能资格。

初轮回放因严格 JSON 对象原型不同而误报冲突，已在严格解析后复制为普通 JSON 数据；保留重复键和可执行字段拒绝。实际 Node `spawnSync` 在当前 Windows 单进程 Job 内出现挂起，连其自身 500 ms 超时也未返回。原生期限能终止整 Job，并保留真实 `timeout` 失败及已释放资源证明；本批不把它描述成已验证的同步子进程错误返回，也不放宽 Job 限制。正常单进程测试不依赖该调用。

第二轮受影响回归 132 条中 131 条通过，旧 OpenCode 撤销场景在原 suspended 证明发布前耗尽启动期限。失败目录没有原启动 / 清理证明；只读核对原 nonce 派生 SID 后确认仍留对应 ACL、Y: 映射和 Profile，已保留，不推定资源释放或根因已修复。旧失败分支丢失捕获的 stdout / stderr；本批补为启动 / 通道失败后保存有限原始输出及明确 `completion_proven: false`、`resource_disposal_proven: false` 的诊断。受控通道失败验证原始记录；后续通过的回归只证明该轮运行，不能替代旧失败资源恢复。完整启动准备阶段监督和原资源恢复仍属 V1-09 待办。

最终受影响回归与固定源码摘要见 [D-225 验证记录](../research/CimiLoop-固定Node检查宿主-2026-10-08.json)。Protocol 242 Schema、原生数据库格式 10、文件账本 / 回执版本 1 与四个公共原生控制源文件保持；凭据读取和外部模型请求均为 0，未升级用户库。
