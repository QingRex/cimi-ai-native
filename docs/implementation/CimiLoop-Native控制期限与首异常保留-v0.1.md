2026-10-09，D-244。正式 Agent 默认入口仍关闭，完整五组 S1 持续实施。

## 本批可执行改变

原控制助手调用现在由独立的 15 秒 AbortController 监督。先发生的外部取消或期限固定其分类；调用开始前、兑现结果时以及异常路径都核对停止状态。即使 Windows 终止以退出码 0 返回、或已输出完整 JSON，也不能将被中止的调用当作有效证明。控制助手不重试，不重开原 Run。正常未中止的非零结构化 Native 拒绝按旧义读取；信号终止、输出超限或损坏 UTF-8 拒绝。

原 Node execFile 的超时成功分支没有检查 killed。本机 Node 24.19.0 的实现已核对；两个实际 Windows 反例分别先输出有效 JSON，然后等待自身期限或外部取消，旧实现均错误接受。新实现独立控制首次停止，不依赖退出码 0 判定超时是否发生，也在 JS 计时器迟到时检查实际 elapsed。

原 Task 时钟监督把最早控制异常传给同一执行 lifetime。准备回调或主执行错误立即中断同一等待与 Native 输入，再按原归属处置资源；后续 EOF、原进程结束或取消不能覆盖首因。原回调 Error 仅在内存中保留给调用方，不序列化其 message、stack、cause、argv、环境或原 stdout / stderr。迟到回调仍被消费，资源按原 late-close 规则关闭。

新的私有 control_failure 保存封闭操作分类、失败类别、退出码、信号、耗时与输出字节数，写入已有 incomplete 原件的可选字段。正常非零退出、终止、取消、期限及无效输出可以区分；killed:true 的输出超限仍可能归为 terminated。分类不是完成、模型账户批准、领域结果或费用结清证明。
