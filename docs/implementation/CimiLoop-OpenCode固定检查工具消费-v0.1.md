# CimiLoop OpenCode 固定检查工具消费 v0.1

日期：2026-10-08，D-227，V1-09 续批。承接 [固定 Node 检查宿主](CimiLoop-固定Node检查宿主与原始账本-v0.1.md)与[启动资源登记 / 恢复](CimiLoop-OpenCode启动资源登记与恢复-v0.1.md)。接通实际 OpenCode SDK 的 `cimi_check`、原进程 IPC 和真实 Node 检查；模型回复、正向准入和预期修改字节仍是明确构造的演练输入，不构成生产 Agent、真实技能或 S1 验收。

## 安装目录固定整个调用链

检查宿主提供严格、独立复制的目录：原 Scope 摘要、Node 二进制摘要、仓库策略摘要、有序检查配方及目录摘要。目录包含原固定入口、全部输入内容摘要和有限期限 / 输出上界，最多 16 项检查、每项最多 32 个来源文件。可信本地组合器在安装 IPC 前固定检查目录，通道安装后不能补装检查或替换目录。

SDK 模块从沙箱中的固定只读目录文件加载配方并复制验证。原生通道 ready 记录携带目录摘要；宿主在放行悬挂 OpenCode 前核对原 OS 进程 / SID、Scope 与目录一致性。请求再次核对相同目录和已安装 ID；原检查宿主保留当前 Kernel 权限与原始来源字节检查。没有安装目录的组合器仍只暴露文件工具。

这些关系固定了私有演练的 SDK / 通道 / 宿主，尚未完成正式 Context / `host_admission_ref` 对检查目录的生产准入核验。目录摘要也不是技能资格、账户或费用证明。

## 模型只选择检查 ID

`cimi_check` 参数只有 `check_id`，Schema 枚举实际安装 ID。SDK 自身的原 session / message / call ID 形成固定 `sdk_` 调用 ID，与文件工具一致；模型不能提供调用 ID、命令、argv、路径、源码、环境变量、cwd、期限或身份。参数在异步 permission 等待前固定，取消和 permission 拒绝不会发起调用。

IPC 帧只携带原 Scope、SDK 调用 ID、`run_check`、检查 ID 和目录摘要。通道继续以持有的原进程身份及实际 OS client PID / AppContainer SID 限定 peer。检查回执复用已有原记录，SDK 核对固定 profile / entry 和完整来源摘要，再提供有限工具输出；完整 stdout / stderr 和原生结果保留在可信宿主的原调用账本中。

命令退出非零或原生超时是 `failed` 检查结果。SDK 工具完成传输可以携带失败结果，不能转换成 `passed`、Task 满足或 Gate 批准。响应丢失不自动重试、不更换原调用 ID；显式回放仍重新核对当前权限和原始完成依据。检查 Unknown 对父 Run 与预算结清的阻断保持。

## 期限、取消和输入边界

原通道 20 秒期限短于检查宿主允许的 30 秒命令期限。本批将通道尝试 / 宿主回复 / SDK 回复分别固定为 120 / 119 / 125 秒，模型不能改变；原命令仍最多 30 秒。原 peer / 控制器退出或通道关闭同时取消文件和检查宿主，关闭等待原操作收束。

这是有限传输期限调整，不是完整 Run 生命周期或所有来源准备的统一期限。32 个来源的读取 / 准备、嵌套方法调用和总 Run 预算仍需正式监督者管理。128 个保留逻辑槽位也仍不是物理硬配额或完整历史容量政策。

当前配方固定输入内容摘要。实际联调在运行前明确提供构造修改后的预期字节，再验证 OpenCode 的实际替换与快照相符；该方式不能代表任意模型修改后的自动新鲜验证。正式验证应在实现后捕获实际新源码，固定新的验证目录 / Context / Run，再执行相应检查；这部分仍需生产组合器接通。

## 验证与接续

实际 Windows / OpenCode 1.18.34 场景覆盖真实文件替换后执行 Node 测试、超过旧 20 秒传输期限的合法检查、失败断言如实输出、Human 在修改后且检查 dispatch 前撤销，以及原检查回执的显式回放。目录文件的真实写入尝试被沙箱拒绝；源码模块 / 二进制保持固定，资源释放核对原生记录。原生 Task / Run / 预算不因工具结果自动推进。

独立契约测试使用明确构造的回复，覆盖目录 / Scope 变化、模型覆盖字段、可执行参数、permission 等待中的对象修改、伪造通过、错误来源 / 入口、丢失回复和取消。它们不是实际命令或真实模型证明。最终受影响回归、源码摘要和失败初轮记录见 [D-227 验证记录](../research/CimiLoop-OpenCode固定检查消费-2026-10-08.json)。初轮实际测试因测试计划仅允许修改单文件而申请整个 src 目录被正确拒绝；随后修正夹具的正式计划范围，没有放宽生产权限规则。

本批 Protocol 242 Schema、原生数据库格式 10、已有文件 / 检查回执格式与四个公共原生控制器保持；凭据读取 / 外部模型请求均为 0，未升级用户库。D-225 缺原登记的历史失败和跨登录恢复仍保持 Unknown。
