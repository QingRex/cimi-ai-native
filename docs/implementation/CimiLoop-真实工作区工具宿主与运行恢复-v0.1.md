> 2026-10-07，D-219，V1-09 续批。已实现实际 Windows 工作区文件句柄、持久工具效果身份及父 Run 结清核验。本地受信 Human 服务可以调用；Agent 权限、IPC / OpenCode 消费、命令执行和完整 S1 尚未完成，继续按 [V1 实施计划](CimiLoop-V1可执行设计与实施计划-v0.1.md)推进。

## 实际工作区边界

[D-208 公开文件演练](CimiLoop-WorkItem工具授权与执行账本-v0.1.md)保留原实现与账本格式。D-219 新增独立的 `authorized_workspace` 宿主，资源路径指向实际项目工作区。`LocalWorkspaceToolService` 从共享本地应用取得 Project、Human 身份、原 RunRecord、实际路径及 Kernel 权限查询；调用输入不能选择另一个项目目录、账户、执行者或新账本。

当前只支持 Windows x64、固定本地 NTFS 卷中的既有 UTF-8 文件，读取与替换上限各为 16,384 字节。没有新增文件、删除、重命名、任意 shell、验证命令或联网能力；`run_checks` 仍没有执行端口。正式 Agent 的权限分支及执行入口尚未安装，所有新工具回执保持 `formal_agent_execution_enabled: false`。

独立 C# 文件代理按源码摘要构建并固定可执行文件摘要。Node 宿主只发送有界规范化输入和一次提交帧；Runtime 不能选择可执行文件、参数、环境或工作目录。文件代理打开卷根、项目根的全部祖先、资源沿途目录及目标文件，持有不共享写入 / 删除的目录句柄直到结束，并核对实际句柄路径、类型、卷和文件身份。拒绝 reparse point、junction、已有硬链接、多卷、设备路径、数据流、路径穿越及任何层级的 `.git` / `.cimiloop` 资源。

准备时核对原文件 SHA-256，保存根目录与原文件的卷号 / file index、实际代理 PID / 创建时刻 / 程序路径。读取持有拒绝写入 / 删除共享的原文件句柄。替换采用共享字节范围锁保护普通数据写入，并在宿主私有目录创建空暂存文件，复制并保护原 DACL，记录其 `replacement_identity`；准备不修改工作区内容。暂存目录与目标必须在同一 NTFS 卷。

原子 dispatch 后，同一代理再次核对原内容、单一链接与实际路径，写入私有暂存文件、截断、Flush(true) 并读取核对，再核对路径当前文件身份并调用 `ReplaceFile` 替换授权路径。原文件的数据不被原地改写；新内容的文件身份在 dispatch 前已经固定，完成后的 `after_file_identity` 必须与其一致。系统替换采用保留原权限 / 属性的 API，受保护 DACL 的实际测试通过，参见 [Microsoft 文件替换说明](https://learn.microsoft.com/en-us/windows/win32/fileio/moving-and-replacing-files)。

补充反例确认普通共享锁仍允许新增硬链接，Batch oplock 也不能阻止该创建；因此没有保留原地写入方案。准备后新增链接或改名会在提交前被拒绝。替换只切换授权路径到新文件，旧文件的已有打开句柄仍读取原内容。读取保留原 UTF-8 字节语义，包括 BOM、空文件及控制字符；非法 UTF-8 拒绝。准备凭据不可复制，内嵌身份不可改写；只有创建它的宿主能提交一次。返回完成结果前还必须确认代理完整退出且输出边界有效。

这些约束保护受信代理的具体效果，不构成整个工作区的文件系统硬配额，也不表示沙箱已经获得真实工作区访问权限。原内容 / 身份核对与系统替换是两步，不是操作系统提供的摘要 compare-and-swap；字节锁也不阻止已有内存映射。不能用这层声明防御同权限 Human 对工作区或私有目录的并发干预，生产宿主仍须落实工作区归属与保护。工具仍通过受信宿主执行，不能据此绕过正式 Runtime 的隔离或准入检查。

## 独立工具账本及授权

项目私有数据目录下固定 `workspace-tools/<project_id>.sqlite` 与策略锚点。独立 SQLite application_id 为 `0x43494d57`、user_version 为 1，不复用 D-208 的公开账本、模型账本或原生领域数据库。原生数据库保持格式 10；239 个 Protocol Schema 均保持，没有隐式迁移或升级用户库。

账本固定 Project、规范化仓库位置摘要、实际根目录文件身份及代理作用域摘要。已存在的锚点、原账本或根身份缺失 / 不一致时拒绝，不重建空账本替代未知事实。同权限本机 Human 改写或移除整套私有文件不在这一保护边界内；受保护的生产保管链及账户唯一性仍须实现。

实际 Kernel 授权在 claim、文件准备前、dispatch 前和实际提交前重新读取。每次缓存重放也重新检查当前 WorkItem、Context、原操作身份、角色、预算、活动 Run 及授权摘要。撤销或身份变化拒绝效果 / 缓存发布；权限查询成功不代替模型或费用准入。

每条记录固定输入、原授权 basis、原 Node 宿主及准备后的实际文件代理身份。顺序为：

1. 实时授权，原子提交 `reserved` 与完整输入。
2. 打开并锁定文件，保存原生准备证明，再核对授权。
3. 原子提交 `executing`，核对当前授权，再发送一次提交。
4. 原生文件效果及完整退出证明通过后，原子提交 `completed` 和回执。
5. 重放原完成回执，不重复读写，也不声称文件当前仍为历史内容。

同 Run 或同路径的 `reserved` / `executing` / `unknown` 阻止新调用；准备后的原文件与暂存新文件的实际卷 / file index 还用于核对跨 Run 的同文件效果，即使替换已发生而完成回执丢失，路径别名也不能消除已保留的 Unknown。原调用键的输入或授权摘要变化视为冲突。原输入、宿主身份、准备证明及已完成回执不可改写或删除；读取时核对精确 Schema、策略、摘要、状态、容量与完成结果的一致性，损坏拒绝使用。

最多保留 128 条调用，每条预留输入、准备、回执、宿主记录四份各 114,688 字节的上界，即 458,752 字节；默认共 58,720,256 字节（56 MiB）逻辑内容容量。Unknown 与未开始记录保留原槽位，不能用失败 / 换键回收额度。该上界不包含 SQLite / WAL 的物理占用，尚不是磁盘硬配额。

## 进程恢复与父 Run

宿主主动停止时先结束并等待自己持有的文件代理，才将未 dispatch 的调用记为 `not_started`。一旦 dispatch 已提交，缺少完成回执均保留 `unknown`，即使文件摘要看似符合替换结果也不能补写成功。完成已提交但调用方未收到回复时，重放原回执。

正常停止先关闭输入，让代理释放句柄并清理自己的暂存文件；15 秒期限耗尽才强制终止。强制退出可能留下宿主私有暂存文件，完整原资源清理仍在后续受控恢复范围，不能据本批声称磁盘资源已全部回收。

崩溃恢复同时查询原 Node 宿主和已记录文件代理的 PID、创建时间与程序路径。任一仍活动、身份无法核定或观测失败，均保留预约；两者都确认为不存在后，未 dispatch 预约转为 `not_started`，已 dispatch 且未完成的调用转为 `unknown`。恢复不按进程名清理，不重启同键效果，也不自动解决 Unknown。

默认 `LocalRunVerifier` 只读查询项目的原工具账本，并核对每个调用的原 Run、operation key、执行者和 Context 摘要。`reserved`、`executing` 或 `unknown` 未结清时，Kernel 拒绝父 Run 的成功、失败、取消结清及 Human 核对结清；允许记录仍运行或未知。已有 dispatch / 完成 / Unknown 事实时，不能以 `not_started` 返还父运行次数。账本缺失、损坏或归属不符得到 `EVIDENCE_MISSING`，拒绝不增加事件或改变用量。

工具完成不自动推进 Task、Run 或 Gate，父运行仍沿用原生结果、费用及证据核验。通用自定义宿主必须接入原工具事实端口；本批未安装生产 Agent 宿主，也未提供把工具 Unknown 人工改成成功的快捷入口。
