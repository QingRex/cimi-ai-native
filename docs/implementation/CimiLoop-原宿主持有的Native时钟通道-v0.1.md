# CimiLoop 原宿主持有的 Native 时钟通道 v0.1

2026-10-09，D-245。完整五组 S1 持续实施，正式 Agent 默认入口仍关闭。

## 本批可执行改变

原 Task 的生产预算改用一个由当前宿主持有的只读 Native 时钟通道。新通道启动时独立读取 WMI boot identity，持有原宿主 OS Process handle，并登记当前宿主 PID、创建时间和随机 nonce。复制旧 Task anchor 不能替代新宿主的真实启动读数。每次读取都是新的请求和 OS 读数；不会用上一份缓存时间给下一步授权，也不会为每次采样新建 .NET 进程。

每次读取前重新核对助手字节摘要，逐次核对 nonce、严格连续 sequence、机器与 boot identity，并禁止 uptime 倒退。Native 每次重新读机器身份、GetTickCount64 和 UTC；保存的 boot 只在同一 held owner handle 存活期间复用。宿主退出时 Native 监测原 handle 并自行退出，不通过重新发现 PID 处理资源。旧单次 --anchor / --continuous 接口仍兼容，用于旧契约核验。

启动与每次读取保留 15 秒硬期限。每次 read 从入口开始计时，排队、二进制核对和回读共用期限；完整输出到达时仍检查实际 performance elapsed，避免迟到计时器接受已过期证明。未发送的过期请求不会产生新 sequence，已发送的过期请求关闭原通道。通道异常或结束后拒绝复用，不自动创建替代助手或重新启动 Run。

取消某一次读取会立即拒绝该调用方，但已发送的原响应仍须被消费。后续读取等待它结束再发送自己的新请求；原响应本身不能给被取消的调用方授权。这样准备阶段监督停止之后，同一预算仍能进入后续启动，而不会因为更换助手、重发请求或取消共享时钟破坏原身份。

队列最多 16 个、单通道最多 8192 次请求、单行输出最多 4096 字节、累计 stdout 最多 8 MiB，stderr 不被解释为时钟证明。异常只有封闭失败类别、操作、退出码、耗时与字节数，原输出、argv、环境和 Error 不进入错误上下文。通道失败中的 stdout / stderr 字节数是原助手自打开以来的累计数，不是单次回读的报文长度，不能据此推断那次采样的产生或传输时间。这些通道限额不是完整 Runtime 物理配额或历史容量验收。

## 生产组合与关闭责任

openLocalAgentRunBudget 持有自己的通道，开启失败会关闭它。AgentRunBudget.close 幂等，关闭后不能再次获取预算。共享 LocalAgentRuntimeComposition 的准备失败、迟到 staged resource 处置和 staged.dispose 都接入原预算关闭；LocalAgentRuntimeStart 保持原 dispatch 前唯一登记及原操作身份，执行结束后处置 staged resource。启动登记只为读取当前机器身份打开短期通道，finally 关闭。测试中的直接预算 / 时钟调用也显式关闭。

原 Task 的不可变 anchor、累计 wall / monotonic 计费、异步授权重核、Native 原绝对 Task deadline 和未知费用冻结保持。通道关闭不是 RunObservation、Task 完成或费用结清；没有借机重开原 Run、释放预算或改写原失败。

## 验证与限制

本批加入排队期限反例：两次各需 14 秒的读取不能让第二次到 28 秒才通过。取消原读、身份不符、字节改变、失效拒绝复用和原预算幂等关闭均有契约回归。实际 Windows 场景验证同一 PID 的多次新读数、取消后继续读取及显式关闭。

宿主死亡测试最初让 stdin 持有者处在原 owner 的子树中，多次观察到零退出码。独立诊断副本记录的是 EOF 路径，不能把它当作 owner monitor 的失败或成功。将持有者移到测试根进程的独立兄弟子进程后，保存完整 Native header，并在原 helper OS handle 上读取退出码 2，验证原 owner 退出而 stdin 仍被独立持有时助手自退。诊断没有修改生产退出码；所有中间失败结果保留。

最终完整源码602文件前后零变化，串行受影响契约8文件67项通过。实际Windows组合5文件10项8通过2失败、0跳过；两份失败的同源码复验2项1通过1失败、0跳过。读改查组合在三次构造模型回复后被clock_continuous硬期限中断，约15.686秒，三项Native效果仍可再核验，原资源已处置但没有提交成功观测。控制延迟的完整原因未确认，不能宣称生产稳定。
